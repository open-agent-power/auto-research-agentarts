# Product working agreements

- For development or refactoring, start with `.agent/README.md` and load `.agent/skills/research-dev-router/SKILL.md`; select the relevant aesthetics, components, backend, interfaces, knowledge, evaluation or references index. Ordinary discussion does not require a development round. This project-local skill location needs explicit loading if the host does not read AGENTS; it is not a hook or guaranteed auto-discovery.
- The current product plan is `docs/plan.md`; adaptive research decisions are in `docs/research/adaptive-research.md`; implemented facts are in `docs/current-progress.md`. `docs/README.md` is the formal document entry. The full ICT workspace keeps archived historical plans and records in `docs/history.md`; they are local and not shipped with the source. Do not turn a proposed interface into a claimed implementation.
- Read `DESIGN.md` before any UI work. The UI defaults to project overview and has distinct research, experiments, knowledge and deliverable pages. Research defaults to an X6 workflow canvas; knowledge uses categorized visual cards, a record reader and a relation view; navigation uses floating glass while long-form content stays solid. Edit `frontend/` and rebuild the packaged `web/` assets, never maintain a second hand-edited runtime theme.
- Keep actual implementation in `src/`, product architecture/design in `docs/`, reusable request examples in `examples/`, and local evidence in ignored `runs/` and private `.agent/` state. `.agent/README.md`, approved indexes and skills are shared navigation, not runtime evidence. External source archives belong to the workspace reference library, never the product code tree.
- Distinguish implemented modules from proposed architecture. Canvas positions and visual connectors must not overwrite experiments, citations, evaluation protocols or research state. A draft question or manual connector does not execute research or establish a scientific claim. The opt-in local demo is an independent bounded script, not an LLM or continuation of the stopped historical run.

- Mission: continuous condition-adaptive research with traceable experiments, evaluated strategy or model changes, and resumable execution. Medical, materials and software tasks share capability interfaces; methods preserve domain meaning. A recipe is an instantiable research design, separate from developer Skills. Topic generation is an entry point.
- Root owns contracts, persistence, integration and final verification. Reuse existing agents; delegate only independent work worth parallelizing. Never revert another contributor's changes.
- The engineering fixture does not establish biomedical, materials or cross-domain scientific validity. A local runner is not an AgentArts integration or an LLM weight-training result.
- Keep execution state, scientific status, and candidate promotion separate. Evaluators and hidden labels must not be editable through candidate requests.
- No arbitrary Python, shell commands, pickle loading or user-selected filesystem paths through the tool protocol. Initial tools are explicitly allowlisted.
- Never commit credentials, private data, browser state, reference repositories, run outputs or local focus checkpoints. Share only the approved `.agent/README.md`, Markdown indexes and named project skills allowed by `.gitignore`; focus, current-workbench, team-budget, worktrees and artifacts remain ignored.
- Use one ignored `.agent/focus.json` for the active development round. Preserve actual failures and missing integration evidence.
- For AgentArts China browser operation or workflow reproduction, read `.agent/skills/agentarts-china-builder/SKILL.md` and follow its links. This custom location does not imply automatic skill discovery by every agent tool. Team assignments and deliverables are in `docs/team-handoff.md`.
- Validate persistent state, idempotency, budget accounting, candidate rejection and recovery with real execution before claiming completion.
- Update only affected indexes and formal docs when capabilities or interfaces change. Keep rules specific and checks proportional; document-only changes do not require model calls, historical fits or repeated full reviews. AgentArts integration remains deferred and existing fee/quota boundaries remain in force.
- UI work must be checked using actual rendered screenshots under the user's visual inspection rules.
