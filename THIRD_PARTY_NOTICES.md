# Reuse and provenance

The local workspace frontend uses [AntV X6](https://github.com/antvis/X6) 3.1.8 with pinned dependencies in `frontend/package-lock.json`. The four packaged browser assets are generated from our TypeScript and shared design tokens; the original third-party packages are installed by npm, not copied reference repositories. `frontend/build.mjs` derives `src/autoresearch/web/vendor-licenses.txt` from the packages actually emitted into the browser bundle, preserving their full LICENSE/NOTICE texts and versions. This file is available at `/vendor-licenses.txt`; dependencies have distinct licenses and are not collectively relabeled as MIT.

The build replaces lodash's environment-detection fallback with the browser's `globalThis` to avoid dynamic script evaluation. No installed package files are edited. The build fails on emitted eval/Function calls, requires local script loading, and does not emit source maps or externally imported runtime modules. esbuild and TypeScript are build tools; their code is not included in the browser dependency attribution list.

Scientific fitting and preprocessing use scikit-learn and NumPy; dependencies retain their own licenses. No foundation-model weights or private research datasets are bundled.

The public [Matbench steels](https://ml.materialsproject.org/projects/matbench_steels) dataset is included as its original 8,836-byte gzip (SHA-256 `473bc4957b2ea5e6465aef84bc29bb48ac34db27d69ea4ec5f508745c6fae252`). Attribution: Matbench contributors A. Dunn et al. / A. Jain; original source: Citrine Informatics, *Mechanical properties of some steels*, dataset 153092. The source marks data as CCA4; this snapshot retains [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) attribution and links. Composition normalization and the grouped holdout are this project's transformations, not the official Matbench evaluation protocol. Full provenance and limitations are in [the packaged data notice](src/autoresearch/data/README.md). Dataset and software licenses are recorded separately.

The optional HTTP transport uses the published [Huawei Cloud AgentArts SDK](https://github.com/huaweicloud/agentarts-sdk-python) version 0.1.8 (Apache-2.0). It delegates HTTP routing, runtime context and handler execution to `AgentArtsRuntimeApp`; its source is not vendored. Dependencies installed in a deployment retain their packaged license notices. The project provides its own bounded protocol adapter and engineering probe; neither implies a Huawei Cloud deployment or a verified platform Trace.

The fixed polynomial fixture is generated locally from an explicit mathematical equation and deterministic random seeds. It is an engineering test only, not medical/materials data, an independent hidden scientific benchmark, or a claimed discovery.

The experiment loop draws on the documented ideas of [AutoSciLab](https://github.com/scientific-discovery/LLM-AutoSciLab) (adaptive experiments and negative evidence), [AI Scientist v2](https://github.com/SakanaAI/AI-Scientist-v2) (experiment branches), and [autoresearch](https://github.com/karpathy/autoresearch) (bounded train/evaluate/keep/reject). Their source code is not copied into this repository. In particular, AI Scientist v2's custom license is not silently relabeled as MIT.

Documentation used for this implementation: [scikit-learn data leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage), [Ridge](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html), [Pipeline](https://scikit-learn.org/stable/modules/generated/sklearn.pipeline.Pipeline.html).
