# 条件自适应研究设计

## 一个未来故事

以下是虚构的目标体验，不是新增研究结果：研究者想找能改善细胞响应的材料，先提供论文与测量表。Agent发现终点身份不清，先核对通道／对象映射；取得实际导出后重新评估条件，再选择分组预测。若几何特征没有改善主指标，它转向误差诊断或提出可区分解释的取证，而非无限调参。研究者回来时看到“查清了什么、还有什么未知、下一步需要什么”，可从同一项目继续。
这不是预定每题必须走的SOP：有可靠终点的项目可以直接检验；没有足够证据的项目应明确暂停原因。

## 统一能力接口与职责

统一的是目标、条件、输入输出及反馈的契约；方法内部仍保留领域特定数据语义。

| 部件 | 负责 | 不代替 |
|---|---|---|
| ProjectState | 目标、证据版本、已知/未知、假设、行动、预算和待办 | 科学真值或通用target字段 |
| MethodCatalog | 方法定义、前置条件、输入输出和评价方式 | 自动认定方法科学有效 |
| Controller | 根据当前条件选方法、读反馈、调整或停止 | 数据适配、工具执行或暗中修复模型答案 |
| ToolAdapter | 把方法实例映射到实际允许的工具，返回结果与出处 | 任意代码执行或完整研究设计 |
| KnowledgeService | 按决策请求检索证据、经验和方法说明 | 把命中、历史判断或外部文档当指令 |

拟议接口伪码：

```python
project = projects.get(project_id)
evidence = knowledge.query(need, project.scope)  # 仅查本地已保存材料
options = methods.match(project.snapshot_ref, need)
# 本例由固定本地策略根据options/evidence产生choice，不在query中调用模型。
spec = methods.bind(choice.definition_ref, choice.bindings, evaluation_ref)
run = runs.start(project.id, budget_id, policy_ref,
                 request_id=start_id, expected_state_version=project.state_version)
accepted = actions.submit(run.id, spec, choice.tool_command,
                          request_id=action_request_id,
                          expected_state_version=run.project_state_version)
result = executions.get(accepted.execution_ref)  # 查询已接受执行，不重提交
# 应用层保存真实结果；completed后重读项目，再按反馈选择下一步。
updated_project = projects.get(project_id)
```

接口沿用研究契约，尚未接线；`need`、`choice`是本地选择的输入/产物，不是另一套执行接口。模型选择、联网search/fetch和新来源提取须登记command及实际资源，不能藏在只读`knowledge.query`中。pending或unknown先按已有执行身份收集/核对；不能直接当作已完成反馈继续依赖它的行动。单个Agent可完成选择，无需按每个部件增加Agent。
宿主附加来源ID、观察哈希和最新行动身份；模型实际选择的方法、参数与理由原样保留，不将宿主绑定称主动引用。
工程结果、数值事实、未审定模型解释与人工核对分别存放；active记忆只是可用状态。

## Recipe是什么

Recipe在这里是一份**可实例化、可比较的研究设计**：解释为何在这些条件下使用这些方法、取得什么反馈以及如何判断下一步。
它可含多个步骤或只有一个检查；既不是研发Agent的大Skill，也不是所有课题强制通行的SOP。
方法定义可复用；实例绑定当前项目的真实证据、数据、参数和评价；执行记录保存实际发生内容。

| 最小字段 | 含义 |
|---|---|
| id / version / question | 方法身份、版本与要解决的问题 |
| conditions | 终点、样本、来源与工具等前置条件 |
| inputs / bindings | 所需输入和实例绑定，保留单位/批次/来源语义 |
| steps / adapters | 可执行方法步骤与允许的工具能力 |
| evaluation | 主指标、比较对象、可核对工件与失败判据 |
| feedback / next_options | 哪些观察支持继续、修订、取证或停止 |
| limits / budget | 不可外推范围、单次执行成本界限 |

### 两个方法实例：同一契约，保留不同终点

以下设计ID与研究契约一致，只映射现有能力，不执行或复制历史控制器。

| 实例字段 | `p02.saved-oof-residuals` | `p02.source-mapping-check` |
|---|---|---|
| 问题与终点 | 冻结候选误差集中在哪些组？终点是同section平坦对照归一化的原始红通道代理值；ALP身份未知 | 现有材料是否支持某一导出列/对象/通道/工作簿映射主张？终点是该主张的证据状态，不是代理值或ALP效应 |
| 样本单位与批次 | 四规则共同870个`(topography, chemistry)`聚合材料键，35整纹理留出折；已知化学类别；不能把spot/section当新独立样本。batch/section处理来自冻结输入，不能由纹理组推断 | 单条映射主张及其来源坐标。batch/section是待核对关系，例如工作表B8S1与实际图像/导出行的对应；未知时保留未知，不计算样本量 |
| 输入绑定 | `p02-diagnostic-source-v1`的真实snapshot、输入/配置、候选行动及预测工件身份；`dimension=chemistry`或`topography` | 原件或已登记衍生片段的source ID、SHA、版本、定位；待核对的对象/图像/测量特征→导出列→工作簿列主张及缺失链节 |
| 处理规则 | 原四规则：`recorded_equal_batch`、`recorded_equal_section`、`positive_equal_batch`、`positive_equal_section`分别报告；不删误差行、不换目标排行 | 原字节与原/衍生身份分开；工作簿值区分缓存/公式/缺失；只核对所给坐标。保存配置不等于实际运行，NaN设置不等于Count=0处理 |
| 比较对象与结果 | 同一规则、同一材料键的`current_candidate`相对`chemistry`；输出n、MAE、有符号偏差、ΔMAE、改善/变差组数及完整行 | 原文主张与实际原件/导出链逐项核对；沿用`source_assessment`的`supported / unresolved / conflicting`，附定位与解释范围，不套用MAE |
| 当前复用入口 | [residual_diagnostics.py](../../src/autoresearch/residual_diagnostics.py)的`validate_source`、`inspect_residuals`纯算术层；完整映射见[研究契约](../architecture/research-contracts.md) | [KnowledgeIndex](../../src/autoresearch/knowledge.py)的`search/read_source`、[tabular_source.extract_selection](../../src/autoresearch/tabular_source.py)与已有[来源评议](../../src/autoresearch/source_assessment.py)记录；它们不是已实现的统一映射判断器 |

两者的条件结果均为`satisfied / uncertain / not_applicable`，和执行状态、主张的证据状态分开：

| 条件结果 | 数值诊断例 | 来源核对例 |
|---|---|---|
| satisfied | 完整匹配的冻结四规则OOF，可对代理值做所选分组算术；不表示ALP资格已满足 | 来源身份、定位和待核对主张明确，可核对指定范围；结果仍可unresolved |
| uncertain | 原始文件尚未取得，无法检查工件/材料键覆盖；先请求对应封存包 | 只有保存的管线配置，没有实际对象导出或工作簿连接；可读已知材料并列缺口，不能确认整个链 |
| not_applicable | 要求用本工具估计ALP效应、spot可靠性、未见化学外验或重拟合；超出工具含义 | 要求从CropRed名称推断ALP、用FTS分数裁定科学真假，或让此方法比较预测MAE；应改用合适方法/取证 |

不同处理规则、模型输入、终点或评价范围改变时创建新实例/版本，不回写旧比较。两实例共用来源和结果关联，不把“来源支持程度”映射成数值性能分数。

## 知识服务的四个决策点

| 决策点与输入 | 读取的材料与定位 | 如何改变具体行动 |
|---|---|---|
| 问题澄清：课题声称研究ALP，只有红色列名 | [数据资格](../chemotopo-data.md)的`B8S1_Normalised!E2`与`B8S1_SNR!E2/E82、G2/G82`及来源SHA，定位数列角色冲突 | 不提交ALP效应比较；保持原问题待补证，可另绑定明确命名的代理值诊断子问题 |
| 设计选择：固定候选未改善化学基线，询问下一检查 | 已保存同规则候选/基线结果与诊断的source snapshot、action ID；[residual_diagnostics.py](../../src/autoresearch/residual_diagnostics.py)的`LIMITATIONS`和允许分组 | 输入完整时选择尚缺的分组诊断或引用既有观察；若所问是spot可靠性，改为索取重复测量，而非调用不适用工具 |
| 执行准备：要绑定导出列、对象与批次 | [管线证据](../pipeline-evidence.md)模块#3、#20/#21及原始逻辑行，配合已取得导出/工作簿坐标；本机缺导出时明确缺失 | 保存配置只能支持设置层核对；转成[实际导出取证](../teammate-pipeline-brief.md)任务，不能由文件前缀或残留列表补齐输入 |

先复用已有FTS索引、来源清单与原文坐标；知识请求返回出处与不足说明，不先替换为新RAG框架。
资料数量不是收益，需观察证据是否改变了正确的研究选择。模型读到片段仍可能误读数值或列名。
数据表、图像及其测量/样本结构作为分析资产保存，交给相应工具读取和计算，不只是转成文本或放进向量库；原始资产与提取证据保持关联。
方法说明、开发平台资料与科研证据分别组织；历史错误判断不能作为已验证科学事实召回。

外部source connector是计划能力，尚未接通：

- 生物医学候选：[Europe PMC官方REST入口](https://europepmc.org/RestfulWebService)。
- 材料候选：[Materials Project官方API文档](https://docs.materialsproject.org/downloading-data/using-the-api)。

先按任务需要选一个connector，核对访问条件、许可和字段；计划URL不是当前接口兼容性保证。
未来外部来源按`已登记的search/fetch command → 原始响应/文件与source ID、URL、版本、许可、内容身份 → 解析与定位 → 本地知识query或分析资产 → 方法条件/行动绑定`进入项目。文本片段送检索，表格/图像保留结构送工具，两路共享来源身份。保存新的外部材料后再重新匹配条件；检索摘要、空命中或接口返回成功都不能单独确认ALP或宣布来源不存在。
connector尚待实现，当前两实例只使用已归档材料。访问失败保留原因、范围和未解决项，转向合法已有原件或具体资料任务；不假装fetch完成。若新材料需要授权或产生费用，沿用现有边界，不自动绕过。

## 两层loop

**内层：真实研究反馈决策。**当前问题→条件选择→工具执行或外部取证→观察→修订假设/下一步。
允许在新诊断后修订判断，避免“先给判断便锁死其提出的可执行检查”；仍只提供当前真正可用的能力。
持续性来自项目状态、反馈与恢复，不来自无限循环或新建目录；遇到无证据、未知执行或预算结束可停。

**外层：少量策略配置改进。**针对已观察瓶颈，保留旧版并在独立任务上评价。
先证明固定流程与条件选择差异，才考虑搜索配置；候选生成、评分、人工和运行总成本都入账。

### 首版θ：只调整下一检查的优先顺序

首版只保留`next_check_priority: residual_first | source_first`。它是方法均适用时的选择偏好，不是绕过条件的权限。阅读深度、检索方式、方法版本、模型/推理配置、工具、输入、预算与评价保持固定；暂不搜索其他维度。

| 配置 | 适用条件与选择理由 | 预期取得的反馈 | 反馈后的替代路线 |
|---|---|---|---|
| residual_first | 冻结OOF完整，问题明确限定代理值，当前决定是误差分布/候选是否值得继续；优先低成本零拟合诊断 | 同规则相对化学基线的组级ΔMAE、改善/变差计数与误差贡献；可区分局部集中与广泛退化 | 负结果若跨多数已观察组，保留反证，转来源条件核对或提出特征表达检查；集中也不自动判为坏数据。工具报身份/覆盖错误时先解决输入，不能换α绕过 |
| source_first | 来源链仍有与当前决定直接相关的未决项，且有可读原件/片段；当前决定是能否解释终点或输入 | 对指定主张的supported/unresolved/conflicting、实际坐标和缺失链节 | 取得足够映射可重新匹配并转数值诊断；只有配置仍无导出就交取证任务或waiting，不以更多同类摘要补成确认 |

下列情况先于两种偏好处理：依赖的执行为pending/unknown时先收集/核对；输入内容身份或材料键不一致时不做诊断；请求ALP结论而映射未知时不放行该结论。明确的代理值子问题可另查资格，不自动替换原目标。缺原件时返回可交回的取证任务；两方法均不适用时说明具体原因，不强行二选一。

**条件变化后的改选例（设计推演）：**随后研究者需判断能否称为ALP改善，新增或重读的原坐标显示数列角色冲突，而实际对象导出仍缺。即使配置为`residual_first`，ALP条件也未满足；改选`p02.source-mapping-check`，对照原件、保存配置和明确主张，返回未解决链节并交取证。若后来真的取得同版本导出、通道/批次/聚合映射，则保存新来源和条件检查后再考虑数值方法，旧代理值结果不倒改为ALP结果。这些新增条件仅为推演，当前尚未取得这些资料。

这些选择不修改隐藏评价、主指标或研究目标来迎合结果；确需修改研究问题时显式记录原因和新版本，不回写旧比较。一次反馈触发改选是内层研究推进；θ是否更好须用后续未参与选择的真实任务比较，不能凭这个故事判定。
[GEPA](https://arxiv.org/abs/2507.19457)是待评估候选，本项目未运行；其提示优化不等于LLM训练或通用科研RSI。
领域模型训练是另一种显式工具任务，单独定义数据/目标/评价；不从外层配置优化推导权重训练已发生。

## 少而具体的运行规则

1. 来源/数据条件不足就指出缺口；有解任务不能以一律拒答取巧。
2. 完成真实执行后才记录观察；同一请求恢复不重复实验，未知发送不自动重发。
3. 反馈可改变下一行动；原始判断与修订并列，来源或方法版本改变不静默覆盖历史。
4. 观察与判断分开，条件记忆按来源/处理/任务范围匹配，条件改变不机械禁止重试。
5. 总预算与停止条件可见，控制器结束、研究暂停和科学问题解决分别标记。

这些规则用于保护实际执行和解释，不继续为每个模型错误添加一层审阅或大量协议字段。

## 用三个真实任务验证价值

选3个由实际使用者提出的独立任务，每项最多两轮；两轮只是试点资源安排，不是全局研究限制。开始前写清当前阻碍、将影响的决定及改变决定所需证据。
P02最多占一项，另外两项来自不同资料/问题；不拆同一表格刷题，也不靠模拟故事当真实使用。

任务征集位置见[团队交接](../team-handoff.md)。P02可作为一个候选；其余两项尚未取得，不预先编造课题或假定老师/数据已到位。每项进入比较前冻结一张任务卡：问题与待作决定、原件/版本/访问范围、可用工具、目前关键未知、一次真实反馈、整项验收/严重错误判据、可核对结论的人。没有足够外部判据的任务只作待专业判断案例，不计自动成功。

| 比较 | 共同条件 | 关键差异 |
|---|---|---|
| A强固定流程 | 同模型、方法知识、工具、输入、执行反馈和预算 | 任务开始前由熟悉该问题的人写明步骤、例外和反馈后的修订规则；允许补证/暂停，不能故意忽视已知冲突 |
| B条件自适应 | 同上，独立工作区，不看另一组结果 | 固定一版θ，根据同一条件与真实反馈选择方法与下一步；不在评估途中换配置 |

## 实施边界

当前先形成可审阅的底层架构，不直接编码；架构定稿后再安排统一项目控制器的一条最小真实路径。复用现有底座需逐项接线验收，不宣称已完成复用。
当前只读工作台仍展示真实历史；新方法设计不改写旧预算、模型回复或科学状态。
沿用免费模型、原5元现金上限与现金结算未知；Codex剩余额度≤5%停止交接，AgentArts接入继续暂缓。
[可行性审查](../../../../references/auto-research/11-recipe-feasibility/2026-11-01/README.md)提供已有研究及反例，不是本产品有效性证明。
