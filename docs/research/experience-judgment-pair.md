# 历史方法案例的同状态计划比较

问题是：在同一真实课题、同一反馈和同一停点下，加入当前实现的历史方法案例，是否使下一份计划增加具体、正确且能改变后续工作的判断要求？案例被提及、文字更多或多一句谨慎说明，都不单独算作收益。

## 固定任务与比较

使用已完成的Auto MPG年份输入对照，冻结state34。父版保留六输入，候选只去掉model_year；同392个完整行、同原生origin三折。父／候选MAE为3.6802006229／5.2858166148，候选优于训练折均值参考9.1486257715却差于父版；负预测2→0并不抵消MAE增加。199次负对照只打乱已保存候选预测的折内行配对，不复算训练，也不验证年份增量价值。

原工具4/4、fit12/12、来源1/1和Host1/1，当前候选0。两份比较都不能执行、扩额或自动采用；这个停点是要回答的问题的一部分。

一份使用当前活动的Yacht案例，另一份从同一原生context中明确移除`experience`并重新封存选择身份。两份目标状态、反馈、父子比较、未决项、候选及预算完全相同。原生plan prompt按各自context生成，因此处理同时包含案例正文和当前产品的条件提示；比较不单独识别二者各自的效果。

使用两个同配置、无父对话继承的代理，各保留一份原始四字段JSON，不从多个有效回答中挑选更好的版本。提前随机分配输入标签；独立审阅时再次隐藏来源标签。正文可能主动说明案例，审阅者可能推知条件，因此这里只是隐藏标签，不能保证对处理条件盲法。

## 原件与复核

[`prepare_experience_pair.py`](../../scripts/prepare_experience_pair.py)仅读当前项目并生成两份context、两份原生prompt和manifest。control明确标为`offline_ablation`，不可当作当前真实项目context发给控制器。重新读取时验证文件原字节、原生prompt再生成及仅案例／必需封存身份变化；不建立Host请求或改变源项目。

```powershell
.venv/Scripts/python.exe scripts/prepare_experience_pair.py --workspace <已有活动案例的项目目录> --output <新的独立输出目录>
```

比较前封存问题、已知事实、失败判据和费用边界；比较后沿原生响应协议核对两份回答，独立判断事实、可执行范围、迁移错误及具体后续证据需求。原协议校验不能替代科研解释审阅。方法说明与运行原件分开，实际预登记、输入、回答和审阅保存在本机`runs/experience-judgment-20261112/`。

## 本次观察

两份原回答均通过原生计划协议，没有重写或重抽样。隐藏标签X对应有案例，Y对应无案例；独立审阅判两份都适合当前关闭状态的文字规划，比较结果为`no_material_difference`。17条审阅引用均与原字段中的确切原句匹配。两份都保留父子MAE退步、负预测2→0、不同参考的范围和停止新增执行的决定。

有案例回答明确写出案例ID、原项目与船体／车辆、分组／原码、目标／单位的区别，并表示不迁入原数值、变换和适用性；这证明原回答中出现了有出处的参考，未构成当前Host采用。它更具体地提出完整OOF、行号、折及未来局部检查条件；无案例回答更细地列出车辆／采集身份、重复测量、纳入过程与不重叠外部样本。两者已覆盖同类判断需求，独立审阅没有找到清楚的单向实质优势。

加入案例使context由33,023增至39,333字节，原生prompt由42,692增至50,133字节。字节变化不是token或费用计量；本次额外内容未对应已观察到的后续研究收益。

代码核对另外指出无案例回答的一处条件性预算表述：“研究.source-selection所需的证据读取及本地工具累计预算获得明确授权”。控制器对来源分支核对来源额度，项目把来源行动与数值工具行动分开计数；来源读取本身不占数值工具或fit额度。这句话可能使接续者为单纯来源读取额外索求本地工具授权，是需要澄清的过度约束，没有在当前状态触发执行。原独立审阅没有提出此项，其原件完整保留；不据此把一次抽样的差别归因为案例效果。

这使下一开发动作更具体：补足方法类别与预算类别的明确对应，并验证“数值工具额度满、来源额度仍有余量”的合法来源候选。优先修正这类可定位表述，不把本次无实质差异改写成扩充经验库的收益。任何后续prompt修订形成新版本及新评测，不回写本次输入或回答。

后续`d1d9380`方法成本输入已另做[同状态措辞核对](../method-budget-costs.md#同状态的实际措辞核对)：两条件保留相同案例，仅成本捕获及相应原生说明不同。预算内容审阅为`both_correct_where_stated`；对照原始JSON格式失败另记，未修写或重抽样。该记录没有覆盖本次案例比较、原回答或`no_material_difference`结论，也不建立科研收益。

## Limitations

这是一个已经参与开发的任务、一个状态、一份案例及每条件一次抽样，没有后续执行、未见任务或真实使用者。即使计划有可观察的积极差别，也不能证明研究结果改善、因果效果或普遍收益；无实质差异也不证明案例永远无用。

原生prompt来自`60d2f12`的生成模块；复核冻结对照应匹配捕获时源码。后续生成器变化会使原生再生成核对拒绝旧输出，不能据此重写本轮原件。

两份评估回答和独立审阅都是实际模型介入的开发活动，与保持不变的项目Host账本分开。具体模型、内部推理次数和费用未知；未调用CLI、AgentArts或其他新模型服务接口，不把代理调用写成零模型活动或零总费用。旧现金边界和历史未知继续保留。
