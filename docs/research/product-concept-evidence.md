# Auto Research 产品概念研究的依据与取舍

实现状态对齐于2026-11-07，外部材料沿用2026-11-06核对记录。本文连接一手材料、实际阅读范围和[产品概念建议](product-concepts.md)，供后续讨论和修改追溯。当前产品比较、能力取舍和平台自动化路径见[横向调研](product-landscape-20261106.md)。

## 11月6日横向调研带来的修订

Elicit已提供可回改的综述步骤，Perplexity公开说明会调整研究路线，当前Kosmos进一步描述持久编码Agent与交互反馈。可修改计划、长期项目和多Agent由这些来源共同确认为已有产品机制。本项目的差异主张转向实际任务中检查依据、作出研究判断和继续工作的体验，收益需要使用证据。[Elicit](https://elicit.com/blog/systematic-review)、[Perplexity](https://perplexity.ai/help-center/en/articles/10738684-what-is-research-mode)、[Kosmos 2026工程说明](https://advances.edisonscientific.com/research/how-we-built-kosmos)

能力方向据此调整为问题具体化、受约束的实际分析、主要结论关联依据，以及AgentArts实际接通。PR #19、#20、#22、#23已合并方法卡、单轮keep/revert、显式项目采用及有效v2的默认后续执行。A64交接材料和state 20报告已交付，后续围绕真实任务、有限多轮接续和平台接通推进，OKS与集群保留为后续方向。完整比较和分阶段结果统一在[调研决策](product-landscape-20261106.md#5-能力引进与优化决策)维护。

## 产品建议与证据怎样对应

“可继续的研究项目、可修改的计划、反馈引起的具体修订”是本项目根据既有目标、实现差距与相关研究形成的产品建议。相关论文各自证明或展示某些机制，整体组合是否适合我们的用户仍需实际使用来判断。

| 建议 | 支持这项选择的材料 | 推论范围 |
|---|---|---|
| 用户能看到并修改正在形成的研究计划 | LitPivot的证据批评与修订交互；Google co-scientist接收研究者目标和反馈 | 值得优先设计具体的修改动作；不能直接推定我们的长期使用收益 |
| 保留持续项目状态和阶段产物 | Kosmos的状态与出处关联；Agent Laboratory的阶段产物和checkpoint | 利用已有项目与工件支持继续和交接；不要求复制相同系统规模 |
| 配方需要适用条件与偏离模板的空间 | AWM的方法与错误分析；本项目原研究契约 | 方法知识与执行顺序分开表达，让新反馈有地方改变路线 |
| 配方优化与课题内调整分开投入 | AFlow与GEPA的受约束优化；DGM修改编码代理的机制 | 先完成可用的研究流程，再考虑有明确评价的系统优化 |
| 执行、研究判断和用户价值分别观察 | ScienceAgentBench、DiscoveryBench、TruthInsightBench的评价对象差异 | 依据本次问题选择少量有意义的验证，避免以执行次数或报告数量代替效果 |

## 一手材料及实际阅读范围

### 工作流 方法知识与系统改进

**AFlow v4**：[原文](https://arxiv.org/html/2410.10762v4)，定向阅读§3—5及附录F。它在预设操作符构成的代码工作流空间内，根据执行和评价反馈搜索；主实验涵盖问答、数学和代码，附录还有学术想法生成案例。这里借鉴流程可表达、可修改、可比较的思路，自动搜索的成本与效果需另行判断。

**GEPA v2**：[原文](https://arxiv.org/html/2507.19457v2)，定向阅读§2—5.1及表1。主要机制是对给定系统的文本模块进行反馈驱动优化，基础模型权重冻结；另有固定代码任务的推理时搜索扩展。它支持保存原版、从失败轨迹提出修改并比较候选；合并候选在部分设置下也会退化。

**Agent Workflow Memory v1**：[原文](https://arxiv.org/html/2409.07429v1)，定向阅读§2.2—3.2.2、表4和附录C。它把具体操作抽象成可参考的流程；§3.2.1讨论工作流引导了与环境不相关的动作及偏离模板的困难，§3.2.2讨论错误流程可能降低表现。步骤级改善与整任务成功分别衡量，经验复用应保留适用范围。

**Darwin Gödel Machine v3**：[原文](https://arxiv.org/html/2505.22954v3)，定向阅读§3与§6。系统修改编码代理自身的工具与流程，基础模型冻结，通过外部编码任务评价变体。这里用于明确自我改进的评价对象，帮助区分保存经验、改变策略和修改自身改进机制。

### 面向研究者的系统与交互

**LitPivot v1**：[原文](https://arxiv.org/html/2604.02600v1)，定向阅读§4.3、§5、§7.1。研究者编辑想法，系统依据论文提供批评及修订，用户可以选择采纳或拒绝；研究想法变化后检查相关部分的一致性。作者报告了17人的短时构思研究。它直接启发“计划局部—相关依据—修订建议—研究者选择”的交互。

**Kosmos v2**：[原文](https://arxiv.org/html/2511.02824v2)，定向阅读§2.1、§3.1—3.2。目标和数据引导文献与数据分析，结构化状态积累结果并生成后续任务；报告关联论文或分析Notebook。论文也讨论过强解释、研究意义判断和专家核对负担，帮助我们将状态保存与科学判断分别设计。

**Google AI co-scientist官方说明**：[2025-02-19说明](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist)，阅读目标输入、假设生成/反思和科学家反馈相关内容。它把人的研究目标、初始想法和自然语言反馈作为输入。借鉴目标、竞争解释和后续验证之间的联系，Agent数量依据实际需要决定。

**Agent Laboratory官方README**：[上游仓库](https://github.com/SamuelSchmidgall/AgentLaboratory)，本次读取阶段组织、Co-Pilot和checkpoint说明。这里参考阶段产物及继续工作的组织方式，后续适配仍按实际任务决定阶段顺序。

**Asta官方发布页**：[2025-08-26发布说明](https://allenai.org/blog/asta)，作为研究体验的背景材料，阅读文献查找、带出处综合与数据分析的能力说明，并保留发布页当时已提供能力与计划能力的区别。

### 科学任务与研究判断的评价

**ScienceAgentBench v3**：[原文](https://arxiv.org/html/2410.05080v3)，本次阅读摘要、§2.3及附录A。它以自包含程序承接科学工作流中的任务，执行后检查任务产物与成本。作者将研究重点限定为科学数据处理、分析与可视化的代码生成能力；有助于确定工程与计算能力的评价范围。

**DiscoveryBench v1**：[原文](https://arxiv.org/html/2407.01725v1)，本次阅读§3、§4.3与附录B。它按条件、变量、关系表示数据驱动假设，并评价预测假设与参考假设的对应。这里借鉴研究问题与结论的结构表达，评价方法仍有参考答案和模型裁判的特定前提。

**TruthInsightBench v2**：[原文](https://arxiv.org/html/2609.05079v2)，本次阅读摘要、§3、§6.1与§6.3。它探索在隐藏原研究结论时，让Agent自行提出主张并审查支持证据。对本产品有用的思想是检查主张、实际分析与可反驳条件之间的联系；不采用其分数作为本产品效果证明。

## Limitations

这是选择性调研，定向读取相关正文、局限和官方说明，没有逐字审阅所有附录，也没有复现这些系统。固定版本论文不能代表所有后续版本；同一论文的多个版本不算独立佐证。官网与README的能力描述属于作者说明。

LitPivot的17人研究主要覆盖短时构思和计算机/信息科学，论文明确不运行代码或实验，长期效果仍待研究。Kosmos v2描述的是2025年系统，2026-05-18官方工程说明已描述交互反馈和持久编码Agent，论文旧版限制分别保留原范围。Google的案例与内部假设排名也不直接证明任意领域的研究效果。

TruthInsightBench仍是探索性预印本：回顾性冻结数据、单一基础模型与单次运行、单一LLM裁判及专家校准未完成，限制了其结论。ScienceAgentBench与DiscoveryBench各自评价特定任务产物或参考结论，不能穷尽开放科学研究，也不能由局部通过认定真实新发现。

论文的任务、领域、预算与指标不一致，本次不拼接排行榜或统一分数。目标用户的真实需求与本产品差异优势仍是待核实的产品假设。现有A64轨迹支持四行工程输入下的单轮决定与有效版本后续执行，真实任务科研收益、真人价值及多轮自主持续RSI仍缺证据。研究检索的结算未知，原项目额度与历史用量继续保留。
