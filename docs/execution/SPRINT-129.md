# S129: fixed white-box synthetic retrieval counterexample

This is an engineering fixture generator, not a Wikimedia dump parser, a rights assessment, an unseen evaluation, or permission to perform research. It accepts no source input, URL, data bytes, or sample-size setting. It creates only a previously nonexistent `runs/s129-synthetic-wikinews-counterexample-*` directory. It reuses the bounded staged source capture/load and original fixed hash salts; no Project, ranking, scoring, model, fit, or dispatcher is invoked during preparation. Process and filesystem guards are cooperative checks, not OS isolation. The original S127 generator and its packet remain unchanged.

The generator fixes IDs 1–1000, derives the 150 query IDs by the S127 query salt, and uses their known identities to deliberately design a distractor for each. The first 50 queries are dev and the next 100 validation. For each query `xN`, its sole positive `d-N` has synthetic text `xN` repeated ten times followed by `yN`; a distinct non-query document has only `xN`. The other 700 documents have distinct `zN` text. IDs 1001–1005 reproduce the first five page titles and bodies to exercise transitive source deduplication: the smaller IDs survive. All articles, labels and synthetic attribution evidence are invented. The packet's document titles are empty and q-/d- identities differ. Thus each qrel points one-to-one to its own document; the deliberately constructed distractor is not a qrel.

The selected split is known when distractors are invented: this is deliberately fitted to the fixture and cannot establish real-world performance, blind validation, or a scientific finding. SHA identifiers bind saved bytes, not authenticity, independent licensing, or loaded in-memory code. Native capture/load validates source structure; this generator separately checks the explicit query identities and generated pair structure.

The previously discussed preregistration for a later, separate synthetic rehearsal would remain `recall@20` candidate-minus-baseline ≥ 0 **and** `mrr@10` candidate-minus-baseline ≥ 0, with met → wait and not_met → saved audit. A mathematical expectation, **not an observed result**, is ΔRecall@20 = 0 and ΔMRR@10 = −0.5: each query has only its positive and its matching distractor; BM25's length-normalized score should rank the repeated-term positive first, whereas TF-IDF cosine should rank the single-term distractor first. With 1,000 documents, the specified lengths total 2,500, so average length is 2.5. For each matching term, BM25 scores divided by its positive IDF are `22/14.26` for the target and `2.2/1.66` for the distractor. No native ranking or scoring has been run to establish that expectation here.

A later two-project rehearsal requires the frozen source, generator, both packet bytes and complete current producer identities to be independently reviewed and published first. It must record the exact same preregistration before either primary, keep each synthetic Project and its budget separate, and retain any unexpected outcome rather than tune the fixture or threshold after observing it. S128's already completed Project and S127 original packet are not reset or reused as a new action. The proposed paired demonstration does not authorize or create a real Project, consume an existing study budget, or establish final/holdout eligibility.
