# S071 — carry waiting decisions into research experience

The existing experience capture required a completed final evaluation, so a project that correctly waited could not pass its reason and evidence to a subsequent plan. A separate `staged-wait-experience-bundle-v1` now captures a completed original conditional manager request while its Project state and snapshot still match that waiting decision. A known outcome rechecks the original primary, action/SQL/artifact and saved feedback. The only supported unknown is `controller_not_started`: no primary, result or value is invented, and prospective primary/controller/child identifiers must not already be occupied. The original context's source scope, holdout metadata, policy, registration and controller identities are checked against the producer. A changed Project snapshot is rejected. `final_status=unmeasured_at_wait` means only that the final was unmeasured at that decision, not that the project can never continue. Offline source binding requires the original manager/Project; hashes are not signatures.

The independent schema is wired through the existing Memory, target plan/report and Workbench selector/card without changing v1/v2/v3 formats. The card distinguishes known zero from unknown/null, tells the user final was unmeasured at the time, and does not imply that later action is blocked. The report recovery identity also now includes the new parser: the old standalone report hash omitted it, although the existing manager Project-core check already rejected parser changes as `CODE_CHANGED`; no working manager bypass was demonstrated.
