# G3-L: target-native method transfer and semantic abstention

The actual cloud Concrete parent/child experience was exported, imported into two new native workbench projects **after their raw baselines**, and retained as historical context. Real Estate's single preregistered house-age mapping modestly improved saved paired error; Slump correctly abstained because it has no varying age input. These results exercise existing native project/design/experience/source/report interfaces. They do not establish a causal benefit of memory, automatic semantic understanding, cross-domain scientific validity or the full original G3 Gate.

Source age is **days**, Real Estate age **years**. `log1p(years)` is a different representation from `log1p(days)`; no unit invariance, coefficient, performance magnitude or physical law is transferred. The useful reusable content is an explicit candidate hypothesis, target-specific eligibility checks, a strict paired evaluation and a warning to inspect local adverse results. Native method association checks domain/method/evaluator; the host's declared-data semantic check handles age applicability. It is not evidence that the generic controller independently understands scientific semantics.

Real Estate groups are coordinate-equality proxies, not verified properties or independent geographic regions. This is grouped interpolation, not future-price or new-region validation. Slump shares one exact ingredient tuple with source Concrete (target No15, source row838); same experimental unit is unverified. It is an applicability negative control, not fully disjoint positive transfer. The two target datasets were purposefully selected, without a no-memory decision arm or sealed unseen task set. Improvement cannot be attributed to the memory mechanism.
