# S070 — import staged research experience in Workbench

Workbench previously rejected all staged v1/v2/v3 experience bundles at file selection and rendered staged cards as if they were Ridge cases, although the backend already accepted these formats. The existing file selector and cards now explicitly recognize staged bundles. The card shows saved baseline/candidate names, development/validation paired results, original feedback and, when present, the external operator rule and comparison; it uses saved final baseline/selected/delta rather than computing research results in the browser. A BM25 same-arm single-computation result is labelled structural zero with the TF-IDF final counterfactual unmeasured, and unknown remains unknown. External shadow remains an operator statement, not a second native registration; offline binding requires the original source. Existing Ridge and CPU paths remain.

File controls now start disabled and remain disabled through the initial project experience load. The initial synthetic browser probe selected before the project loaded and timed out; another waited only for enabled and encountered the same ordering. Both failures are retained in `runs/s070-verification`. One separate malformed synthetic XSS case was rejected HTTP 400 before the manager accepted it because JavaScript reserialization changed numeric JSON bytes; its error and fixture were retained, but that rejected request ID was not saved and cannot be resumed. A later independent correctly byte-edited synthetic case was accepted as its own case; it was not a reset of a prior request.
