# S074 — 工作台计划案例引用与原请求恢复

工作台计划编辑器现在允许操作者显式选择当前 active 的历史案例，并为每条引用填写适用范围与差异。保存包含原 `case_id`、版本和 bundle SHA 的 S073 计划引用；这只是操作者声明，不证明模型采用、因果影响或科研收益。原来的四字段计划仍可使用，未选案例时请求不添加空引用。原案例已退休或升级时，界面保留原身份和声明并阻止直接保存，须由操作者先移除旧引用、再决定是否明确选择其他版本。新计划不会自动更新先前登记；原反馈可能变为未知，或后续评价受阻。

包含案例引用的新计划请求，在 manager 接受时同事务保存版本化的原请求 body、digest、Project/source/manager 身份和原状态绑定；canonical body 上限为 192 KiB。待恢复列表只展示身份、状态及可恢复性，不返回原 body 或声明；`plan-resume` 依据服务端保存的 body 使用原 ID，成功响应只返回修订身份。原 body 仍在本机 manager 持久存储中，不应将本地数据库或完整项目文件视为已脱敏。旧 intent 没有原 body 时标为不可自动恢复，不猜测内容；损坏或异常状态也保守显示并阻断。当前 Project 超过 8 条 pending 时显示总数与截断提示，保守阻断，不能声称全部历史记录均可自动恢复。同项目不得用新 ID 绕过 pending，其他 Project 的操作按各自状态处理。

恢复区分两个持久化窗口。若 manager 已接受、Project 尚未保存，恢复前必须核原状态、Host 快照、来源文件实际字节、源码身份和案例仍有效，再按原 body/ID 提交；来源或状态漂移则停止。若 Project 已保存该 ID 的修订、manager 尚无完成回执，按原修订及历史案例绑定核验并补回执，不因案例后来退休而重新选择或派发；两种窗口都要求原来源文件和源码身份未漂移。`replayed` 标明原请求身份，不能单独解读为恢复过程中一定没有写入：第一窗口可能首次保存计划，第二窗口只补 manager 回执。项目和 manager 的两个数据库不是单事务，intent 先持久化以使中断可审查。
