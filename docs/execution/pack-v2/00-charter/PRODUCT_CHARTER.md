# Product Charter

## 1. 核心定位

Autonomous Research Lab 是一个**面向真实问题的持续自主研究工作台**。

研究者提交研究问题、真实数据、相关资料和约束。系统围绕同一个课题持续保存问题、研究路线、方法、行动、证据、失败尝试和未决事项；根据方法适用条件和真实反馈选择下一步；执行分析与取证；将判断连接到真实来源或计算工件；修订计划并继续研究；将经过验证的方法经验复用于后续课题。

不是通用 Agent 平台、纯文献问答、论文生成器或固定流水线报告工具。

## 2. 核心循环

`研究问题 → 研究计划 → 方法选择 → 实际执行 → 证据分析 → 修订计划 → 下一轮研究`

每个研究循环必须回答：
- 当前问题是什么？
- 当前计划为什么这样安排？
- 选用的方法在什么条件下适用？
- 实际执行了什么？
- 得到了什么真实观察和工件？
- 哪些证据支持、反驳或无法判断？
- 新结果改变了什么？
- 下一步为什么这样选择？

## 3. 四项核心价值

### A. 围绕问题持续研究
保存当前问题、研究路线、已有结果、失败尝试、未决事项、累计预算和运行身份。下一轮承接前一轮，而不是依赖聊天摘要重建状态。

### B. 根据条件和反馈选择方法
用 Research Recipe 表达方法的适用条件、材料需求、输入、评价、成本、限制和结果分支。反馈可触发继续、改道、补证据、等待或停止。

### C. 判断连接真实证据
Agent 输出是提案和解释；工具产生执行回执、观察和工件；控制器核对权限、条件、预算和身份；独立评价器验证结果。结论必须能回查原文、数据、代码、日志或计算工件。

### D. 研究可接续、可复用
另一成员可理解已做事项、路线变化原因、可靠结果、失败路线和下一步。跨项目复用的是带适用条件和来源的经验候选，而不是无条件复制结论。

## 4. 两层改进

### Layer 1 — Intra-project Adaptive Research
同一课题内，根据新观察改变假设、方法、步骤、优先级和研究范围。

### Layer 2 — Cross-project Method Improvement / RSI
跨课题分析真实反馈，改进 Recipe、方法选择、计划策略、记忆策略和 Harness。候选可以完整修改自己的代码与策略，但必须在隔离工作区执行，由独立任务集评价后晋级或回滚。

## 5. 近期主场景

研究者带着真实表格数据和相关资料，完成一项可检验的探索性研究。

必须覆盖：
1. 数据和资料登记、身份及来源；
2. 字段语义、质量和映射检查；
3. 研究问题澄清、假设和竞争解释；
4. 计划生成与修订；
5. Recipe / Method 条件匹配；
6. 实际计算、统计或模型实验；
7. 结果与证据分析；
8. 反馈改变下一轮计划；
9. 结论范围、失败路线和不确定性；
10. 报告、复现附件和接续安排。

## 6. 长期领域
材料、生物医学、软件工程及与实际问题相关的交叉研究。不同领域必须有各自的终点、数据语义、方法条件和评价标准。

## 7. 扩展评测场景
软件研发和零人工运维作为 Agent 闭环能力的主要扩展评测；客服和金融风险/理赔作为后续扩展。它们用于验证方法迁移，不改变产品核心定位。

## 8. 成功标准
- 至少一个真实表格研究课题完整闭环；
- 至少一次真实反馈引起有依据的计划修订；
- 关键结论连接原始证据或计算工件；
- 失败路线和未决事项可见；
- 项目能由另一成员接续；
- 至少一次跨课题方法/策略候选改进被独立评估；
- RSI 的多代持续收益只有在多轮、留出任务上复现后才可宣称。

## 9. 非目标
不训练基础模型权重；不做通用 Agent 商店；不把客服/金融/运维做成首版独立产品；不引入没有证据必要的微服务、Kubernetes、Kafka；不把报告生成、Agent 数量或代码行数当作成功。
