# Benchmark Master Plan

## 1. 评测目标
评测工作台能否持续推进真实研究问题；方法选择是否合适；新证据是否改变研究计划；研究结果是否可追溯、可复现；跨课题方法改进是否有收益。

## 2. P0 主评测：真实表格探索性研究
首个任务必须使用真实、许可明确、字段语义可核验的数据及相关资料。任务由研究问题、数据、资料、字段字典、约束、评价协议和领域审查点组成。

最低任务链：
1. 登记来源、数据版本和哈希；
2. 数据质量、缺失、异常、重复、分组和字段映射；
3. 澄清研究目标与可支持结论范围；
4. 提出至少两个可区分的假设/解释；
5. 形成可执行计划和停止条件；
6. 选择适用方法并解释条件；
7. 执行真实分析/实验；
8. 评价结果和不确定性；
9. 根据观察修订计划；
10. 执行下一步或明确补证据/停止；
11. 输出报告和复现包；
12. 由另一成员接续项目。

## 3. RAG Research
固定语料和查询集，比较 BM25、Dense、Hybrid、Chunking、Query Rewrite、Reranker。使用 BEIR 子集及自有固定任务。指标 Recall@K、MRR、nDCG、延迟、成本。开发/验证/封存测试分离。

## 4. Algorithm Research
选择 CPU 可运行、确定性评价的组合优化/调度任务。先 correctness/property tests，再比较目标值、时间、内存和稳健性。参数优化、代码优化和新算法假设分开报告。

## 5. 扩展评测
- Software Engineering：精选 SWE-bench 任务或真实 issue 子集，作为 Agent 工具执行/研究能力扩展。
- IT Operations：OpenTelemetry Demo 或确定性故障注入环境，验证日志/指标/Trace 到诊断、模拟修复和健康检查。
- Customer Service / Financial Risk：仅作为后续合成或脱敏任务，不进入本轮核心成功标准。

## 6. 对照组
A 固定配方/确定性流程；
B 单 Agent；
C 固定多 Agent；
D 动态 Agent；
E 动态 Agent + 条件研究记忆；
F 跨课题改进后的策略/RSI 候选。

相同任务、数据、模型、工具、预算、时间、重试。按任务配对比较，记录所有尝试和失败。报告均值/方差/置信区间（样本允许时）；小样本明确限制，不声称统计显著。

## 7. 指标
研究质量：问题理解、假设可检验性、方法适用性、证据覆盖、结论边界、反证处理。
连续性：计划修订引用新观察、恢复正确、无重复行动、交接可理解。
效率：达到有效判断的成本、Token、CPU 时间、无效行动比例、人工介入。
跨课题：方法选择、负迁移、迁移效果、策略改进。
安全和证据真实性为硬门槛，不得被总分抵消。

## 8. 评价器完整性
隐藏标签和 evaluator 受保护；候选不得读取 holdout；evaluator hash 预先冻结；LLM judge 必须固定 rubric 并人工抽查；记录 evaluator 版本和所有失败。
