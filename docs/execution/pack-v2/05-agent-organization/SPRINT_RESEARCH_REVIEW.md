# Sprint Research / Build / Evaluate / Investigate / Decide

每一大轮必须按以下顺序：

1. Research：检查现有实现、上游、论文、替代方案；
2. Hypothesis：明确本轮预期改进及可证伪条件；
3. Plan：任务、基线、评价、预算、停止条件；
4. Build：动态子代理并发实施；
5. Evaluate：真实任务、对照、失败记录；
6. Independent Review：检查代码、数据、证据、成本、安全；
7. Investigate：重新调研是否有更成熟或更简单的方案；
8. Decide：保留、修改、回滚、延期或停止；
9. Update：更新 ADR、路线、任务板和研究记忆。

复盘必须回答：
- 解决了哪个真实研究问题？
- 哪些真实行动和工件证明？
- 新证据改变了什么计划？
- 哪些方法失败、为什么？
- 研究质量/效率/连续性是否改善？
- 有没有成熟项目已更好解决？
- 架构是否仍合适？
- 下一轮最高价值实验是什么？

不得因沉没成本继续原方向。
