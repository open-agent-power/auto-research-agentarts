# Sprint 001 — G0 云端接入与可执行性验证

## Research / Hypothesis / Plan

从已存在的研究工作台接入执行包。假设：现有项目/预算/证据/计划结构能够复用，不必先重写；当前云机能否提供计划要求的Worker隔离必须实测。输入commit和原包身份均已固定。任务按源码、上游、数据、资源及独立审查拆分，按文件所有权并行。

## Build / Evaluate

- 解压并核验原包、克隆指定仓库、建立接续入口与30行实现/验证矩阵。
- 固定8个上游commit，读取3核心及相关扩展源码/许可；初始27路径中26个AST成功、1猜测路径缺失保留。AIDE²仅方法审读，代码可用性未建立。没有安装运行第三方框架。
- 官方Concrete的许可、字段、1030行与哈希已核验，准备逐token无损转换；已见历史结果明确披露，没有启动真实课题拟合或产品模型请求。
- 真实Docker探针发现CPU/RAM/PID参数未生效；其他非root/只读根/无网络/capabilities/tmpfs检查保留独立证据。修正false-pass风险并增加离线安全回归。
- 完整工程基线初次缺h5py，补本地依赖后暴露两处测试可移植性问题；修复Windows解释器路径和显式外部资产配置，保留所有原内容断言。专项与完整回归的实际结果见[基线](g0/baseline-verification.md)。

## Independent Review / Investigate

[独立审查](g0/independent-review.md)复核资源原始输出、上游HEAD/文件哈希、数据原件及测试修改。关键纠正：docker inspect不是限制生效证据；任何写失败不能当tmpfs容量证明；数值前缀不能精确匹配限制；已见Concrete题不等于未见任务；静态AST不等于runtime smoke。

上游审读说明成熟项目仍有作用域、执行权限及许可代价，没有证据支持一次性引入多个框架。现有原生控制器是后续首课题的最小入口。

## Decide / Update

保留现有架构和准备好的真实课题。**G0保持BLOCKED**：先恢复可强制执行资源合同的Worker，再完成所需上游隔离PoC，独立审查后才解锁G1。没有因进度或已投入时间跳过Gate，没有开启持续后台研究、自修改候选、外部付费或生产部署。

下轮最高价值动作是用同一资源探针核验修复后的环境；通过后按固定课题协议运行两轮，检查观察是否真正改变计划与行动，并由另一成员独立接续。当前没有研究质量/效率/持续RSI收益主张。
