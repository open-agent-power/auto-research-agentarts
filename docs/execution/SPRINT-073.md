# S073 — optional explicit case references in plan revisions

A saved research plan previously had only four free-text fields. It could mention an experience in prose, but could not bind its exact identity to the plan revision. An explicitly supplied `experience_case_refs` envelope can now carry one to four `{case_id, case_version, bundle_sha256, applicability_statement}` entries. This is an untrusted operator statement that the plan references a case, not proof of model adoption, causal influence, or scientific benefit. The old four-field plan, context and prompt remain byte-compatible; existing Host plan responses still do not generate references. This slice adds backend/API and report support; it does not add a Workbench editing control for the new field.

New plans are checked inside the Project writer against the then-latest active case revision and actual stored bundle bytes. Duplicate case IDs, invalid statements, version types, hashes or unknown fields are rejected; the manager preflights new requests but the Project lock remains authoritative. The exact ordered original body is used for replay. Historical plans are checked against the latest applicable case revision before that plan's `based_on_state_version`; later retirement or replacement cannot rewrite history or block a completed original-ID replay, while new plans cannot cite retired cases. An accepted but not saved request whose Project changes remains the original intent and returns stale state rather than silently adopting a new case. The saved plan's base version must be strictly earlier than the current version; a pending write may base on the current version.

The existing preregistration binding is not relaxed. Changing the plan before primary can make the original feedback `controller_binding_changed`/unknown; changing it after a primary leaves that original feedback intact but the current policy waits and the original holdout freeze is rejected. References do not create candidates, extra budget or new model calls. The report lists each reference separately, preserving all identities and full bounded statements in Markdown and PDF. A previous candidate joined them into one line, causing later references to be truncated by report display; the failure and independent reproduction are retained and the fixed version was checked with four 1,000-character statements.
