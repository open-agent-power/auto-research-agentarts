# 持续自适应研究：实施主线

## 要交付什么

让研究者围绕一个长期问题持续工作：资料与数据进入项目，Agent根据条件选择研究方法，调用真实工具，读反馈并调整下一步，最后交付可追溯的结果和未决问题。
持续研究可以包含假设检验、数据分析、数值训练或外部取证；不要求每轮训练，也不把报告数量当研究进步。
最终交付包括AgentArts实际编排下可继续的研究项目、论文式PDF与复现附件；医疗、材料、软件工程垂类及有实质问题联系的交叉研究使用同一架构。初赛路径以公开或可合法取得的数据为基础，不依赖私有数据。
P02是已运行案例；统一项目能力面向后续课题，不把其红通道代理值或专用Ridge协议变成所有领域的默认语义。

## 稳定主线与可调细节

| 稳定主线 | 随真实反馈调整 |
|---|---|
| 项目状态、来源身份、行动结果与累计预算持久化 | 控制器具体提示与交互形式 |
| 同一能力接口连接方法目录、控制器和工具适配器 | 首批方法数量、检索策略、领域连接器顺序 |
| 按条件选择，执行反馈改变下一步 | 方法内部步骤、参数及小范围策略配置 |
| 观察、模型解释、人工判断分开保存 | 报告模板和用户操作细节 |
| 用真实任务和强基线评价研究推进及用户价值 | 后续是否值得引入配方搜索或GEPA |

研发Agent使用的Skill是开发操作指南；产品运行时方法是研究设计与执行契约，两者不共用一个“通用大Skill”替代内核。
少量清楚的规则优先：条件不合时说明缺什么；执行完成才记结果；未知发送不自动重发；新版本不改写旧证据。

## 六项讨论的设计落点

| 已确认的决定 | 当前具体设计 |
|---|---|
| 统一能力接口，按条件自适应选择实现 | [底层架构](architecture/foundation.md)的职责/依赖与选择流程；[研究契约](architecture/research-contracts.md)的项目、运行、行动与反馈 |
| 配方是可实例化、可比较的研究设计 | [自适应设计](research/adaptive-research.md)的Recipe字段与实例；开发Skill、运行时指南、方法和工具分开 |
| 知识参与决策，外部数据按来源接入 | 自适应设计的四个决策点与来源候选；底层架构的文献检索/分析资产分流 |
| 两层迭代先复用、轻量比较 | 自适应设计的内层反馈与少量θ配置；阶段四按需要评估GEPA，不依赖大规模训练 |
| 规则清晰、适用，避免题库和协议堆砌 | 研究契约的最小执行边界；自适应设计的少量运行规则与真实任务验证 |
| 价值必须有外部依据 | 阶段三的强基线、相同资源、真实反馈，以及研究推进/用户收益两类判据 |

下一实施项：让任务绑定的来源资料提交、登记、读取与知识反馈也从工作台完成，继续沿原方法/来源账本，保留原文坐标、未读/失败/unknown与未核验解释。材料、来源内容不能充当命令或授权；同一项目依据新反馈继续，不重复已完成分析或把声明当领域批准。真实模型和平台仍依原授权边界推进。

交付：模块职责与依赖、项目/运行/行动/观察边界、方法与工具接口、知识数据流、AgentArts接入位置，以及对应开发索引和提醒Skill。
验收：能沿一个项目解释数据从哪里来、谁作决定、谁执行、如何保存反馈；正常结果、反证、缺条件和中断恢复四种路径没有职责冲突。
现有实现与目标接口明确分开，首个适配入口可定位；架构文字、伪码和故事都不算已运行。
架构轮仅交付可审阅设计；随后 A4 已进入限定本地实现。该切片不建立 REST 服务、不启动新研究，目标架构的其余模块继续分阶段实施。

当前选择：首个 adapter 为已有 `residual_diagnostics.inspect_residuals` 的同步纯算术层，保留 P02 冻结输入限制；首版 θ 只含 `next_check_priority: residual_first | source_first`，仅影响两个合资格检查的顺序。数值诊断和来源核对两个实例、四条状态路径已写入研究契约；来源/方法/评价含义不因统一对象而合并。A0–A3 与仍未取得的资源见[交接](team-handoff.md)。

## 阶段一：统一项目控制器最小真实路径（A4–A7 有限三域已实现）

首个任务见[架构基线的 A4](architecture/foundation.md#首个实现任务a4本地切片已实现)：单一本地 OOF adapter→真实反馈→下一决定→跨进程恢复。已用固定规则策略完成本地接线与跨进程验证；模型选择和 HTTP 入口未实现。未知结果、结果未提交、重放/复用及内容冲突已定点验证，历史研究保持冻结。实际入口和限定证据见[本地项目切片](project-slice.md)。这不等于阶段一完整的通用控制器已交付，后续仍需方法目录/选择抽象和知识条件的真实接线。

## 阶段二：方法实例与知识决策服务（三域本地子集已接线）

依赖：阶段一接口可用。
交付：少量可实例化方法、条件匹配说明，以及问题澄清／设计选择／执行准备／反馈解释四处知识请求。
先复用现有FTS和原文定位；只在实际漏检或误读出现后比较检索改进，不先建新向量平台。
外部connector首个有限实现为Europe PMC DOI元数据；Materials Project仍待实际需要、访问与许可确认。原始ID、版本、URL、许可和响应身份进入来源清单。
验收：资料能改变一次具体选择；缺失证据会形成可执行取证任务；检索命中不自动成为科学结论。
connector的接通、数据资格和科研作用分别验收，不把计划链接写成已接入。

A5 已在原 A4 项目显式升级后接收真实归档材料，执行工作簿/文本选区读取，建立现有 FTS 索引，并把实际引用送入四处决策上下文及下一决定。来源不完整仍 waiting，不能自动放行 ALP。两方法目录有条件/未决执行/已完成复用语义；持久项目默认 residual_first，尚无策略切换命令。跨域目录、外部 connector、模型解释及独立任务价值尚待推进。

A6 已把同一项目的真实记录与检索接入既有工作台只读页面，并完成实际截图/交互与接口验证。接下来需把独立钢材/软件任务接入同一项目能力，逐步解除 P02 专用条件；已有 M01/S01 技术反馈不算阶段三配对价值验证完成。

A7 已完成这一步的有限实现：三个主方法通过显式注册表共用同一项目持久化/恢复，材料和软件已各执行真实工具、读取来源上下文并保存下一决定；领域终点/单位/协议分别保留。开放式方法扩展、模型选择与策略切换仍待推进；跨域界面/报告由后续 A8 接线。材料选区一次真实失败和修正被保留，不以完成率掩盖用量或自动重试。

A8 已把三域实际项目接入同一界面组件，导出绑定快照的 JSON/Markdown/PDF/完整输入/清单；过期和损坏报告拒绝下载。P02 原五页与 X6 保留，材料/软件独立打开自身项目。页面、报告与本地用法见当前进度；没有新增拟合或模型请求。

A9 补齐比较前的实际执行断点：来源可先登记为未读，再由统一 `next/advance` 选择并执行一个合资格方法；父请求的选择冻结在原项目内，重放只恢复原子行动。已有一次真实钢材跨进程链路与必要恢复/竞态检查；未做配对或用户价值评价。

## 阶段三：三个真实任务的配对价值验证

依赖：前两阶段可完成真实反馈回路；由实际使用者给出问题与决策需求。
交付：3个独立真实任务、每任务最多两轮、相同工具/模型/预算的固定流程与自适应流程比较；两轮只是本次试点的资源安排，不限制产品持续研究轮数。
每项至少提供一次真实反馈，观察是否调整行动；P02最多占一项，不靠切表扩充任务数。
先锁整项关键要求和严重错误判据，评价人核对原数据、执行工件和报告，而非只给文字打分。
研究推进：减少哪些关键未知、完成何种区分性检查、是否据反证修订、下一决定有无证据。
用户价值：接手到决定的时间、核对/返工时间、实际采用情况、避免的无效工作与继续使用意愿。
验收：按任务公开配对差异与失败；无增益、额外成本或新增严重假批准，不支持当前自适应设计。
三个案例只能给出可用性与改进线索，不证明显著性、跨域普适或自主科学发现。

## 阶段四：少量策略配置的受控改进

依赖：阶段三显示自适应有潜力，且有可核对的反馈与独立评估任务。
交付：围绕一个实测瓶颈比较 `next_check_priority` 的两个配置；两者都先检查资格，仅在同样合资格时比较先残差还是先来源，所有候选总成本入账。阅读深度、模型、检索、工具与预算固定。
先人工可解释配置，再决定是否试GEPA；GEPA只是候选优化器，本项目尚未运行或证明收益。
开发反馈用于选配置，评估任务冻结；不同时换模型、检索、工具与预算掩盖归因。
验收：新配置在未参与选择的任务上优于原配置且成本可接受，才作为新候选采用；失败保留原版。
这层优化改变策略/提示，不等于模型权重训练、自动发现方法或RSI成立。
本阶段是可选优化支线；若未获收益，保留简单策略，仍可推进项目交付和领域适配。

## 费用与工作方式

沿用可用免费模型及既有免费额度检查，不购买或付费回退；原5元现金上限与现金结算未知状态保留，换项目不重置。
Codex剩余额度≤5%停止并保存交接；供应商余额、现金上限与Codex额度分别记录。
AgentArts产品接入继续暂缓；历史独立代码节点成功不等于产品已接通平台。
每轮一个可验证结果，先做必要的受影响检查，再走一次真实路径；仅对变更或失败处补查，不默认重跑全量。
新增方法和策略要能说明解决了什么实际问题；发现旁支先记录，不为凑完整架构立即开发。
