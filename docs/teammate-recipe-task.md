# 配方与RSI板块长期分工

更新于2026-11-05。队友持续负责配方与RSI板块，按待办开发、定期反馈、提交PR。主开发检查并合并后，队友更新主线、继续下一项，贯穿11月提交和后续产品迭代。

队友维护研究方法卡、条件匹配与选择说明、反馈驱动的配方和策略改进、版本采用与回退、轮次接续，以及这些能力的实际使用改进。主开发负责研究计划、控制器、真实模型和工具入口、页面与平台整合。

先用一个可替换实例接通完整流程。后续从实际轨迹和使用反馈中选一项产品问题，提出改动、完成必要验证、决定保留或回退，接着处理下一项。已有配方实现与接线见[接入记录](recipe-research/integration.md)。

## 从这里开始

1. 拉取最新`main`，阅读[长期任务书](recipe-research/team-module-handoff.md)和[接口约定](recipe-research/team-module-interface.md)。
2. 从任务队列第1项开始，开自己的分支，实现方法卡读取与候选关联，使用[现有示例](../examples/recipe-improvement/README.md)熟悉输入输出。
3. 每个实际开发日反馈完成、卡点和下一步。每周二、周五安排PR交付窗口，完成一个独立能力可以提前交。
4. PR合并后拉取主线，按任务队列和本轮反馈开下一条分支继续。主开发接续真实接口和产品整合。

任务队列、阶段效果、文件分工、简报格式和PR接续方式统一在[长期任务书](recipe-research/team-module-handoff.md)。两份起步PR之后继续推进真实闭环、实例复用、用户反馈和方法经验积累。本月整体效果见[11月提交计划](research/submission-plan-20261130.md)。
