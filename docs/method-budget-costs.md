# 方法的额度需求与当前剩余量

控制器把一次新派发需要覆盖的额度保存到`selection_context.conditions[].budget_cost`。它沿用实际执行器的预算分支，帮助研究者及模型区分方法需求与当前余量，不改变方法资格、参数、候选或授权。

| 已注册的方法类别 | 本地工具次数 | 来源读取次数 | 拟合尝试 |
|---|---|---|---|
| 读取已登记来源选区 | 0 | 1 | 0 |
| 普通检查、保存预测核验及负对照 | 1 | 0 | 0 |
| 固定Ridge训练验证 | 1 | 0 | 当前绑定设计的真实需求 |

Ridge需求同时计入训练折内Scaler与Ridge的fit；例如3折组验证需6次拟合尝试。没有该检查的可用设计绑定时，`estimator_fits=null`，含义是未确定，不能当作免费或自行补值。来源读取使用独立来源额度，数值工具额度用满本身不会阻断合法来源候选。

```json
{"method_id":"research.source-selection","evaluation_ref":"source-extraction-only-not-scientific-approval","budget_cost":{"local_tool_calls":0,"evidence_reads":1,"estimator_fits":0}}
```

成本字段恰含三类需求，已知值为非负整数；只有拟合可为null。它不表示当前有材料、方法前提已满足或仍有额度。合法候选仍由原控制器根据实际来源、反馈、设计、未决请求和累计用量生成；未知执行继续保留原请求。

## 建议与历史快照

`plan_readiness.assess_plan_readiness`只复制条件中实际捕获的成本，新增`plan-readiness-v2.method_budget_costs`。未捕获成本的历史context仍产生原`plan-readiness-v1`，不查当前注册表回填旧Host。

选择、计划与配方prompt在包含成本快照时追加同一说明：来源只用来源额度，普通检查用本地工具额度，训练使用捕获的拟合需求，null保持未知；这些数据不授予执行许可。不含成本的旧context不追加这段说明，原回答及prompt保持当时版本。

工作台研究页展开“模型建议与原请求”，再展开“当前方法的额度消耗”即可阅读，模型CLI关闭仍可查看。当前表只接受匹配当前项目、版本及快照的context；历史计划卡分别显示请求准备时的成本，旧记录明确标注当时未捕获。手机表格在局部横向滑动时固定方法名与分组标签，额度始终能对应到方法；页面本身保持正常宽度。

## 报告与复现

新报告的`execution_conditions`保存导出时的当前条件，`input.selection_context`保留其完整依据；两者与`plan_reviews`中的历史请求条件分别保存。Markdown／PDF列出当前方法成本，原始数值及快照在JSON中保留。当前需求与已用／预留／剩余量各自有明确含义，不能通过报告中的需求值恢复额度。

这些数值针对一次新派发的预算需求。已完成请求沿原ID重放复用结果，不追加用量；unknown不自动重发。拟合实际用量仍按原已开始fit事件记录，预留和中断恢复沿原账本处理。

## 本轮核对

工程夹具中，数值结果使用既有持久化夹具，来源仍经真实适配器执行一次。在本地工具和拟合额度用满、实际来源已登记且有余量时，控制器保留合法来源候选；完成及原ID重放后，数值工具／fit用量不变。另一个2组Ridge夹具实际记录Scaler和Ridge各2次，共4次fit，与捕获需求一致。它们不是新的真实科研结果。

原Auto MPG保持state34／计划3、Yacht保持state63／计划8及各自全部预算和Host。当前组验证需求分别为6与10次fit，仍不产生任何可执行候选。两份当前报告更新了成本说明，原输入、行动、模型回答和历史报告继续保留。

## Limitations

首版覆盖当前已注册的来源、普通检查及固定Ridge预算分支，不是任意实验工作流或现金费用估算。新算法和远程执行仍需按其真实执行语义接入，不能套用现有常数。

这是针对已观察到的来源预算表述补足事实输入和阅读说明；未取得新真实模型回答或后续研究结果，不能据工程通过宣称模型解释错误已经消失或科研质量提升。旧的案例有无比较及其无实质差异结论保留不改。
