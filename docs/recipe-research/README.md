# 第一版科研配方：零值后的下一项核对

本轮把研究者写下的优先顺序转换为现有宿主候选中的一项选择。两份 JSON 的问题、适用范围、need 和等待规则相同，仅交换方法顺序。它们是有限候选选择配置；完整研究设计及科学适用条件保留在本说明中。

## 真实问题与当前材料

默认真实问题改为：**hiMSC 的 Count 和红/绿色强度中的零值表示什么，声明的 Topo/Chem 分组是否具有实验含义，目前能否判断？** 2026-11-03 已收到队友补件中的 A16 / himsc-final CSV、spec、来源声明、已保存质量/分组/来源抽取结果及历史 context；11 月 1 日审查笔记也已收到。数据来自声明原工作簿 B8S1!A1:F973 的已保存单元格投影，不求值公式、不删除零值或重复行，完整工作簿未交付。补件和各文件身份见 [gaps.md](gaps.md#补件身份与已保存反馈)。

保存反馈有 972 行，Count、Mean_Red_Intensity、Mean_Green_Intensity 各 59 个零；声明 Topo/Chem 分组 288 组、每组 3–6 行，各数值列的零值分别落在 56 组、单组最多 2 个，完整重复额外记录 3 条。这些是机械统计，不解释零值原因、逐行共现、重复来由或样本独立性。source-selection 仅抽取宿主 spec，仍为 `mapping_status=unresolved`、`endpoint_eligibility=unknown`、`scientific_validation:false`。目标 Mean_Red_Intensity 的单位为 unknown raw intensity proxy、状态 declared_unconfirmed，不能改称 ALP。零值原因保留未知，暂不改值或删行。

钢材保留为目标无零的输入条件对照：补件的 A16 CSV 是 [`src/autoresearch/data/matbench_steels.json.gz`](../../src/autoresearch/data/matbench_steels.json.gz) 的两列原序投影，目标重命名为 `yield_strength_MPa`，不是作者原始发布的 CSV。gzip 为 8,836 bytes，SHA-256 `473bc4957b2ea5e6465aef84bc29bb48ac34db27d69ea4ec5f508745c6fae252`，312 条，原字段为 `composition`、`yield strength`；原目标零值 0、范围 1005.9–2510.3 MPa，与补件保存统计相符。官方固定元数据支持对应数据哈希、字段和条数，不支持实验批次解释。来源见 [sources.csv](sources.csv) 第一项和[包内数据说明](../../src/autoresearch/data/README.md)。

[`datasets._parse_composition`](../../src/autoresearch/datasets.py) 把公式里未出现的元素填成数值 0，再归一化为固定 14 元素的原子分数。这是钢材派生特征规则，不是目标测量零的解释，更不能解释 hiMSC 强度零值。项目组成分组也不是原始实验批次，不能证明样本独立。

## 为什么比较两种顺序

| 配方 | 优先候选 | 预先提出的有用条件 | 不能据此下的结论 |
|---|---|---|---|
| `tabular-group-first` | `data.grouped-quality-profile`，再 `research.source-selection` | 已有主质量反馈、已声明且有意义的分组，需要先定位异常分布 | 集中即错误、批次导致零值、分组独立 |
| `tabular-source-first` | `research.source-selection`，再 `data.grouped-quality-profile` | 已登记但未读的资料可能解释当前字段/编码，而分布尚不能解释语义 | 资料已读即可靠、抽取成功即科学批准 |

同一方法多份来源或多个候选，沿宿主顺序取第一个精确匹配的候选；配方不排序来源、不改参数。只在 `method_id` 和字符串 `evaluation_ref` 都相同时匹配；本 schema 不表达宿主允许的对象型评价引用，因此对象型评价候选不会匹配。若优先方法没有合资格候选，再看下一项；有宿主 blockers、范围或 need 不匹配、两项都无候选则 wait。结构非法或 context 封印无效应报错，不产生可执行提案。

`scope_match={domain:data,contract:tabular-quality-v1}` 只证明工程输入范围符合，不检查测量单位、样本独立性、分组来源或科学评价是否成立。`need=next_check` 是原宿主选择请求的绑定值；`question` 是研究者说明，不执行其中的文本。`on_no_match=wait` 禁止另造方法。两份配置均固定 `version=1`，配置修改要另行记录版本与实际影响。

## 可用、不可用及仍缺什么

| 核对点 | 可用条件/宿主已有检查 | 不可用例子和所缺证据 |
|---|---|---|
| 表格身份 | 捕获的 CSV/spec 原字节、哈希、字段精确匹配；主检查已完成 | 另一钢材表或只拿同名文件，不能沿用本表来源解释；补原 CSV/spec/导出清单 |
| 数值/单位 | 机械统计可描述有限数、零、空串与声明 missing token | 不能以 `zero>0` 自动解释缺失；补目标/字段单位和作者编码说明 |
| 分组/样本 | 宿主允许分组画像且有声明列、预算和前序结果 | 无分组列，或把组成组当独立实验批次；补原始采集/试样/批次定义 |
| 来源 | 当前项目真实 task_ref 下登记的、尚未读取且允许读取的收据 | 只有 URL/资料标题不是候选；不能编造 task_ref 或把另一项目收据接入 |
| 评价 | 使用宿主固定的质量/分组评价与来源抽取评价 | 没有真实标签、领域解释或专业复核；保持 `scientific_validation:false` |
| 恢复/预算 | 使用原 context、原状态版本、原请求 ID 与原预算 | 过期提案、unknown 或已耗尽预算；不能换目录/修改 context 绕过 |

具体不适用反例：只有上述原始 Matbench steels gzip 的钢材模型复核项目，其 domain 为 materials，且不是 `tabular-quality-v1`。两份 data 配方都应等待。即使先转换成表格，若没有 batch 声明，也不能构造一个“批次分组”候选。当前没有对应原项目 context；这里给出的是可核查的适用条件，不伪造实际编译记录。

## 反馈与下一决定

人工固定流程先核对文件/字段/来源，再看已有质量结果，必要时读已有分组结果，最后决定仍需什么证据。保留该强基线，不删除其来源核对步骤。补件前“先定位具体 CSV/spec”的取证决定已完成；当前 hiMSC 的保存分布已有记录，继续数零不能替代采集/导出解释。两配方的先验有用条件仍是假设，不是已证实收益。

本次真实反馈是“hiMSC 的文件身份、机械计数和前序链路已补齐，但 source-selection 只回读宿主声明，仍不能解释零值与实验意义”。下一决定收窄为向数据负责人/领域队员索取此版本的采集/导出、单位/终点和分组/重复定义，不重复读取同份 spec、不补值或删行。三个历史 context 各只有 0/1 候选，不能拼成同一真实双候选，真实分歧与收益仍未知。完整缺口见 [gaps.md](gaps.md)，工程实验由依赖本说明的原型 PR 单独记录。

## 验收、失败判据与成本

第一轮文档验收：三项来源可定位、两个 JSON 可解析且除 id/方法顺序外相同、等待与不适用条件明确，未取得证据没有写成已验证。第二轮工程验收：同一冻结双候选 context 上两配方选不同合法候选，通过原 validator，原控制器只执行 group-first 一次，原请求重放不增加工具行动；用明确标注的人工夹具核对 8 行、4 组和 2 个零值。

若无双候选、顺序不起作用、接受额外参数、配方改变输入、篡改 context 后仍通过或重放增计费/行动，即为工程失败，保留失败记录。工程成功仍不能证明比人工或固定流程更好。真实问题若原件不对应、没有真实反馈、没有专业判断或缺原分组解释，真实效果保留未完成。后续要声称优势，需先冻结同资料、同工具、同预算及未参与调参任务的比较方案。
