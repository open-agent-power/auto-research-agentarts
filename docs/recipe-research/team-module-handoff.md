2026-11-07对齐。PR19、20、22、23已合并，方法卡、单轮采用／回退、项目有效版本、页面采用及默认后续执行均已交付。A64有效v2已完成一次分组画像并导出state20报告，该四行工程样例已收口。后续聚焦真实问题、外环阶段接续与有界多轮改进，实际范围见[RSI交付](rsi-delivery.md)。[A64材料](a64-rsi-handoff.md)作为已冻结工程证据复用，开发日简报及周二、周五PR窗口沿用。

队友持续负责配方与RSI板块，主开发负责研究计划、控制器、真实模型和工具、页面与平台整合。本分工覆盖11月30日团队提交目标及后续迭代，优先级随实际反馈调整。

## 长期要做出的效果

研究者提供问题、材料和条件，系统知道哪些研究方法适用，说明选择理由，并依据执行反馈调整下一步。研究流程暴露的问题进入RSI外环，外环提出一项配方或策略修改，经必要验证决定保留或回退，下一轮沿当前有效版本继续。

队友把这块能力持续做成产品。工作按“发现问题 → 实现一项改进 → 必要验证 → PR → 检查与合并 → 更新主线 → 下一项”循环。主开发维护整合与反馈入口，双方共用本页任务队列。

## 持续负责的内容

| 责任 | 队友持续维护 | 产品中看到的效果 |
|---|---|---|
| 研究方法知识 | 方法目的、依据、输入、条件、评价、来源和反馈分支 | 能解释为什么适用、缺什么、什么反馈会改变下一步 |
| 配方读取与选择 | 方法卡读取、条件匹配、实际候选关联和选择说明 | 当前项目得到适用方法与理由，计划可以使用这些结果 |
| 反馈驱动改进 | 从轨迹定位问题、生成候选、调用相关验证、形成采用决定 | 一条实际反馈引起一项可核对的配方或策略变化 |
| 版本与持续推进 | 原版和候选、采用或回退、轮次接续、下一项问题 | 离开后能继续，当前使用哪个版本可以查明 |
| 使用与知识积累 | 实例复用、实际用户卡点、适用条件和来源补充 | 一次使用发现的问题进入下一次产品改进 |

资料研究围绕当前要实现的能力进行。已有材料缺少方法依据或适用条件时，队友可自行寻找公开论文、作者说明和官方资料，记录原链接、定位、采用理由及限制，再把结论落实到方法卡或实现。资料与代码版本随PR一起说明。

## 反馈和PR节奏

暂按北京时间安排，每个实际开发日结束前发一条短反馈，每周二、周五各安排一次PR交付窗口。能力已经完成可以提前交。尚在开发的工作更新现有Draft PR，写清当前代码、卡点和预计下一次交付。排期变化在反馈中说明。

反馈直接发团队沟通渠道，PR中保留对应代码和结果。使用下面四行即可。

```text
完成了什么，以及对应提交或PR链接
实际运行了什么，结果怎样
当前卡点，需要主开发补什么
下一步准备改进什么
```

主开发收到PR后，在下一次整合时检查受影响的调用和用户流程，问题修复在同一个PR中推进，通过后合并并回复合并结果与下一项优先级。确切处理时间随实际开发安排反馈。

队友在等待整合时，可以整理后续方法依据、定位问题和准备独立任务。依赖当前PR的下一项在它合并后从最新主线开工。这个节奏持续沿用，职责范围内的已列待办可主动领取。

## 每次合并后怎样继续

1. 确认PR已合并，保存本轮结果和下一步。
2. 切回`main`，执行`git pull --ff-only origin main`。
3. 读取主开发的整合反馈，从本队列选依赖已满足且最能推进产品的一项，写一句本轮要改善的具体问题。
4. 从最新主线创建下一条`feat/recipe-<topic>-<date>`分支，实施、验证并提交下一份PR。

下一项优先从同轮阶段接续或真实任务暴露的配方问题中选择，分支按本次问题命名。沿[A64材料说明](a64-rsi-handoff.md)复用已有原件与结果，再推进真实研究联合闭环、实例复用与使用改进。

## 验证与PR交付

每轮先写明想改善什么，以及哪种结果会决定保留或回退。配方读取与关联检查输入、候选身份和理由，复用已有检查。RSI状态涉及候选采用、拒绝或中断接续时，针对相应行为验证。模块开发可用标明构造身份的输入，真实效果由联合运行取得。

已有节点的结果仍适用时引用原记录，新验证围绕新增或改变的连接。每份PR说明本轮问题、变更、实际命令或操作、结果、待接入部分和下一项。源码、使用说明与相关必要检查一起提交，运行材料按仓库约定保存在本机。

真实RSI验收保留实际轨迹、一项由模型或开发Agent提出的修改、相关验证和保留或回退决定，并展示随后一轮怎样利用结果。提出候选、代码合并与实际采用分别记录到对应对象。

## 需要协调时怎样处理

遇到公共接口变动、依赖调整、资源不足、执行状态未知或超出文件归属的问题，先保存当前状态，在反馈中写清所缺输入与主开发要采取的动作，再推进队列中独立可做的一项。实际模型、工具、平台和资源使用遵循当次明确配置，累计用量继续关联原项目。

## Limitations

单轮决定与有效配方由外环目录保存，原项目在线采用、实际后轮和页面接入仍待完成。A64为四行构造工程实例，实际模型提案和工具记录用于工程接线，科研收益另需对应证据。开发日简报、周二和周五窗口及阶段目标按实际进度调整。
