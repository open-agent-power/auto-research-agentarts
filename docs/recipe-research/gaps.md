## 一条完整的真实反馈记录

问题及原件：默认钢材 CSV 零值语义；该 CSV 未定位。能核查的是包内 Matbench steels gzip，身份见 README，不能冒称已取得 CSV。

输入与检查：2026-11-03 对现有 gzip 只读解压，核对字段、312 行、目标零计数与范围；同日阅读固定 commit `9fca4fde11617279096e194ebe72e3a0bf48477e` 官方 `dataset_metadata.json` 的 `matbench_steels` 条目，并查本项目特征转换。

反馈及出处：官方条目的数据哈希/字段/条数与本地对应；原目标无零；`datasets._parse_composition` 的缺元素填 0 是派生特征的明确代码行为。这是可定位的一手分发信息和本项目代码/原件反馈，没有作者私下确认。

反馈前下一决定：先考虑零值分布是否集中，以判断下一项取证。

反馈后下一决定：先取得所指 CSV/spec、字段和变换身份，再读取对应来源解释；不对全部 0 套缺失规则，不擅自生成分组或运行旧模型。若只有不匹配的 materials 项目/无分组，则两配方等待。

核对者和范围：开发助手核对字节、计数、公开字典和代码映射；没有老师、作者或领域队员确认零值的实验含义。数据负责人尚未给出默认 CSV 的可分享身份。

是否有帮助：对发现“可能混用原目标与派生特征”的问题有具体排错作用；对两个配方是否改善真实科研决定目前无法判断，未观测同一真实双候选 context。

成本：只读本地核对，不执行研究项目工具、模型或拟合；新增付费/云调用为 0。最多三项关键一手来源，重复定位不算独立来源。人工耗时未测量。工程实验另计两次实际本地研究工具，不把资料检索冒充零成本。

## 反例与停止条件

1. 公式省略某元素导致项目特征为 0，不足以把所有零值标为缺失。反过来，也不能由这个编码规则声称原实验确认该元素绝对不存在；需要作者/采集证据。
2. `group_columns=[]` 或只有组成组、无实验批次定义时，不能解释批次集中；分组方法无合法候选就看下一项，全部不匹配则 wait。
3. 当前 materials/保存模型项目不是 data/tabular-quality-v1；即使标题都写“钢材”，范围不符也等待。不能编辑 context 增候选或换项目重置额度。
4. 引用字段字典只能解释对应文件版本；没有同源身份时不能把另一数据集字典套进当前 CSV。未可靠取得对应资料与专业判断，保留“零值含义未知，暂不改值/删行”。
