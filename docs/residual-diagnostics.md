# 从预测失败继续研究

实际35个纹理组中，正计数两规则均24组更差、11组改善；保留零两规则均26组更差、9组改善。模型“所有组都更差”的判断错误，还混用了加性模型组6／9与当前候选组6／36。随后被拒绝的判断捏造了未执行的ANOVA/Kruskal-Wallis检验和`p < 0.001`。末两次只有正文，没有合法控制调用；部分汇总表虽正确，仍有错误解释，未成为有效修订。控制器因`REQUEST_LIMIT`结束，研究状态仍active，不能称自主完成或正确自纠；这些原文不写入已验证知识。

重复尝试正则化强度后，当前交互候选仍未超过同规则下的化学基线。下一项任务是查清误差分布与处理条件，再决定要改模型表达、核对目标定义，还是停止这一方向。

这条路径使用已经保存的留出预测，不重新拟合，不更改旧实验，也不删除误差较大的材料组合。输入来自一个已停止、仅含一个完成候选的配置化研究及其精确匹配的封存报告。

## 研究者可以选择的工具

| 工具 | 输入 | 实际产生什么 |
|---|---|---|
| `inspect_residuals` | `topography`或`chemistry`，以及理由 | 四种规则下，各组样本数、MAE、有符号偏差、相对化学基线的误差差值；总体及误差集中程度 |
| `compare_policies` | 理由 | 相同材料键在四个固定对比中的目标变化、残差变化与各自MAE |
| `record_diagnosis` | 方向、观察、下一项检查、理由 | 保存模型提出的未审定诊断，不改变数据资格或执行新实验 |
| `pause`、`stop` | 理由 | 保存实际控制决定；也允许未分析即停下 |

每个分组维度、规则比较和诊断记录最多各做一次。记录诊断后只提供控制工具；最后一次请求也只提供控制工具。累计请求上限固定，重启不会重置。

完整分组和逐行算术结果保存在行动记录中。模型上下文提供确定性的有界摘要：全部总体指标、组数及改善／变差计数，另列有限个最大误差差值组，并明确截断。固定来源、观察身份及最近反馈由程序绑定，不能解释成模型自己选取了引用或已读完所有行。

## 如何解释这些数字

- 按纹理留出是原先的探索协议；按化学切片是已知化学类别内部描述，不是独立化学外验。
- 误差贡献同时列样本数与MAE，避免把样本多的组误判为更差；集中度不证明异常或测量错误。
- 零记录处理会改变目标。不同目标下的MAE不能作为选规则的排行榜，也不能靠删除某类记录宣称模型改进。
- 当前冻结表没有spot级重复测量，不估计测量噪声下限、可靠性或因果机制。红通道代理仍未确认ALP。
- 诊断不触发模型训练、数据清理或平台操作；后续实验需要明确可执行的协议。

## 代码与运行

`residual_diagnostics.py`负责封存来源和确定性算术；`diagnostic_research.py`复用已有SQLite请求账本与免费云调用边界，增加有界研究工具。当前运行入口为`scripts/run_diagnostic_research.py`。

`max-new-requests 0`只准备并读取，不调用模型。实际执行需要既有Ollama免费云别名与冻结的账户范围；没有付费回退。运行结果以当次原生记录为准，不要求模型必须得到支持原假设的结论。

## 阅读与交接

`scripts/export_diagnostic_view.py`只读核对实际原生绑定一次，输出`diagnostic.json`与清单；可附独立`p02-diagnostic-assessment-v1`核对标记。标记绑定原source SHA及判断行动ID，只能unreviewed或needs_revision，不是科学批准。发布后由[独立工作台](portable-workbench.md)读取快照，不反复打开原研究DB或重做数值检查。
