# 继续未完成的来源评议

## 开始、查看与恢复

1. `dispose(actor='operator_assistant', reason=<明确放弃等待的原因>, reasoning_profile='low')`保存一次不可变的处置记录。它表示开发助手决定放弃等待旧未知结果，不是用户或作者的科学批准，也不是撤销旧请求。
2. `status()`只读查看原预留、处置和续接状态；不产生请求。
3. `advance(max_new_requests=0)`只恢复已收到且保存的响应。只有明确传入客户端并设置`advance(client=..., max_new_requests=1)`才允许最多一次新的原生请求；客户端仍须遵守既有免费额度检查与无付费回退范围。

原累计上限为4，旧3次预留仍计入，本次只使用余下1次；不是另起4次预算。新续接单独记录`low`推理规范、4096输出上限与32768上下文，按实际模型能力确认命名级别（见[Ollama推理说明](https://docs.ollama.com/capabilities/thinking)）；原`high`请求与规范不改写。额度检查在既有1美元免费额度底线与新请求0.10美元预留之外，继续保留旧未知请求0.10美元余量，不把未知费用当作已释放。工作流锁阻止并行推进；恢复不自动删除锁、重置预留或改用其他模型。

从产品根运行，以下前三条不会发送模型请求：

处置保存在`continuation-v1/disposition.json`；新预留、响应与结果也只写该旁存目录，原calls/actions不改。默认传输收据目录为`history/continuation-transport-000001`；如显式指定`--transport-output`，须使用新目录。重复查看或恢复沿用同一旁存预留，不增加总请求机会。

## 两种恢复不能混同

`received`表示响应已捕获，可以本地消费、绑定已有行动，不再请求模型。`sending`且结果未知不能按同一请求重发；处置后的一次新请求有独立身份，原未知记录仍可追查。若新请求也未知，应保留其预留并停下，不通过复制目录获得额外机会。
