# 本地研究工作台

## 当前证据怎样进入报告

报告前部的“最新来源核对与未决问题”直接展示最新已完成来源行动中保存的提交者、原主张状态和未决问题，明确标为“提交者记录 / 未经作者或科学确认”。登记但未读取的资料、失败的读取不会成为最新结论。该段至多展示6条主张和6条问题，完整记录保留在JSON。

来源节选按最新读取优先，同一来源SHA与定位使用最新展示主张，PDF至多展示8处并说明省略数量。报告JSON、重现输入和原行动历史仍完整保留。检索也优先返回最新已完成来源索引的实际命中，避免旧证据占满默认限额；这只代表宿主返回了片段，不表示模型阅读或科学确认。补资料、明确读取后，仍需显式生成当前版本报告。

## 启动与范围

在产品根启动独立的本机服务，root须为专用工作台目录，不能指向一个既有研究项目：

```powershell
Set-Location 'D:/XiangMuLuoDi/Development/ICT/track2/auto-research'
.venv/Scripts/python.exe scripts/serve_local_workbench.py --root runs/my-local-workbench --enable-local-actions --port 18791
```

打开[项目总览](http://127.0.0.1:18791/#/overview)。`--enable-local-actions`显式启用本地命令；省略时不接受本地写操作。左侧五页导航贯穿当前项目，沿用毛玻璃外壳、实色内容卡与X6。总览另有[原P02研究工作区](http://127.0.0.1:18785/#/overview)入口，其原课题和封存记录独立保留；该服务需按[原项目用法](project-slice.md)启动。

| 页面 | 入口与操作 |
|---|---|
| 项目总览 | 查看课题、下一任务及资源；展开“切换项目或创建课题”录入CSV或切换已保存项目 |
| 研究推进 | 默认查看真实问题、来源、行动、反馈与待办画布；展开“开展下一步”使用单步、模型选择、资料登记和有界批次 |
| 实验中心 | 阅读当前项目实际方法结果、失败和反馈，下载对应完整行动记录 |
| 知识空间 | 查看已登记原件、实际提取的原文与坐标，检索已读取来源 |
| 成果与复现 | 阅读当前快照报告摘要，取得匹配的PDF/JSON及原记录/输入 |

切页保留本页内存中的输入、操作草稿与原请求状态；不执行方法，不重新请求模型，也不增加额度。画布实线仅对应原记录引用或前序绑定，虚线只表示项目包含记录；移动节点和保存浏览器布局不改研究账本。

模型调用默认关闭。需要使用已获授权的本机Claude CLI时，在启动命令中同时加上原生可执行文件路径：

```powershell
$claudeExe = 'C:/path/to/claude.exe'
.venv/Scripts/python.exe scripts/serve_local_workbench.py --root runs/my-local-workbench --enable-local-actions --claude-executable $claudeExe --port 18791
```

路径换成自己已经安装的原生 `claude.exe`，不要传Volta的 `.cmd` 启动包装；浏览器不能指定可执行文件、命令或提供方。CLI使用本机已有认证和路由配置，可能联网，并依其配置产生费用。省略 `--claude-executable` 时仍可创建项目、明确选择本地方法及阅读已有模型记录，但不能从页面调用模型。已有工作台继续使用原root，保留项目与累计记录；换目录不重置旧模型或历史现金边界。

## 从问题推进一次

1. 填课题，选择CSV/TSV。页面只读本地表头，让使用者勾选数值列、分组列和键列；至少1个数值列，分组与键可以不声明。完整CSV仍由宿主校验，表头预览不等于输入合格或科学可用。
2. 填数据标签、每行含义、来源、许可，以及可选的target/unit。明确选本地调用上限1或2；字段角色、单位和独立性仍是声明。普通使用者不必手写JSON，也可导入已有spec填充专家声明，再在表单中调整。
3. 点击“创建项目，不执行方法”。此步只封存输入并建立项目，随后显示真实条件与候选；不会自动执行首个候选。
4. 选择一个实际候选并写理由，可勾选当前context中的真实来源引用。点击“明确执行所选候选一次”，或明确保存本次等待。每个新决定单独提交；等待只对应本父请求，不代表所有方法耗尽或整个项目暂停。
5. 核对下方保存的结果、来源与未决问题。新的选择和报告在上方明确提交，阅读结果不会自动继续研究。
6. 点击“生成当前快照报告”，再下载匹配的PDF/JSON。项目有新行动、新父请求，或宿主模型记录/原件变化后，旧报告stale，需重新生成；生成报告不继续研究或追加工具分析。

直接填写时默认`missing_tokens=[""]`，`provenance.origin_sha256`为所选CSV**实际原字节SHA**，description明确只是直接捕获本CSV、上游未核验；来源自动给本次上传SHA的URN，仍可由使用者填写真实来源。导入已有spec时保留其missing/provenance声明，表单变更会生成本次spec，原导入文件不被改写。不能把导入声明、公开链接或许可文字当成已核验事实。

## 用模型选择并执行一步

在“研究推进”展开“开展下一步”，找到“模型选择与执行”。这条入口复用[正式宿主模型请求](host-model-selection.md)，模型只能选当前合法候选或等待，不能写工具参数、扩大额度或批准科学结论。

1. 先查看当前候选及条件。没有候选、已有阻塞或原请求未收口时不能新发模型调用；没有合资格行动就先补证据，不花一次模型调用重复等候。
2. 首次填写累计决策限额、累计CLI报告估值上限及允许推进的范围。限额为1至8次，估值上限为正数且至多0.10USD；每次准备请求即占一次名额，首次保存后限额与理由固定，后续沿用，不能换ID扩额。
3. 点击“用模型选择并执行一步”。宿主先冻结真实context，再调用一次既有CLI并保存原始回答；回答合法才交给原控制器，最多执行一个行动。每次下一决定仍要明确点击，不后台循环。
4. 核对保存记录中的模型解释、实际路由、控制器结果及错误。`applied`表示已提交控制器，是否完成以`outcome.status`为准；解释不是实验结果。
5. 需要恢复或核对时，点击该记录的“核对原请求”。此操作使用原ID和原上下文，已完成行动直接返回原记录；unknown不重新发送模型。刷新、换页或重开只读取已保存状态，不创建新请求。

面板分别显示原生本地模型已用/允许/预留，以及宿主CLI启动尝试、已知报告估值和未知用量。原生计数0不代表没有外部LLM调用；`Claude CLI`也不证明实际路由为Anthropic。子代理导入的内部推理次数、模型与费用仍可未知。原5元现金上限及历史unknown费用继续保留，CLI报告估值不是账单。

每条记录可展开查看完整上下文并下载原请求JSON。当前报告包包含宿主模型摘要、原请求及已有原件，PDF和Markdown分别列出原生与外部用量；原生计数仍不表示全部模型使用。完整字段与过期规则见[模型报告包](host-model-selection.md#a28报告包包含宿主模型记录)。

## 按配方推进一步

进入“研究推进”，展开画布下方的操作区，在“按配方推进”中选择“先看分组，再读来源”或“先读来源，再看分组”。页面显示实际配置版本、方法顺序和当前预览；预览由同一项目的真实候选编译，读取或换选项都不执行。

点“按此配方推进一步”才会提交最多一个合法行动；没有匹配候选时可明确保存本次等待。完成后读取新反馈，预览可能转到后一项方法。配方不启动模型、不改变工具参数或增加额度，原始值、未知和来源要求继续保留。它与“模型选择与执行”、手工选择、有界批次分别操作。

刷新会先停用旧预览，再核对项目、版本及 context；读取失败保留配方选择并显示错误，不能提交旧预览。换页保留选择。请求身份、原配方、原版本和实际结果由既有控制器保存；网络结果不明时核对原请求，不能换 ID 重发。方法选择记录区标明配方 id/version、顺序与取舍，完整原件和报告仍沿用原入口。

网页只读接口为 `GET /api/local-workbench/recipes`，固定读取两份正式配方，返回 `project_id/state_version/context_sha256/recipes`；每项包含 `recipe/decision`。无活动项目返回 null/空列表。`POST /api/local-workbench/advance-recipe` 只接受 `request_id/project_id/expected_state_version/recipe`，沿用启动写操作开关、本机会话、活动项目和未完成操作限制，`need` 固定为 `next_check`。配置全文进入原请求，原 ID 重放保留当时的配置与 context，不重新选当前候选。CLI 用法见[配方集成](recipe-research/integration.md)。

## 在同一项目登记资料，再明确读取

“补充资料”面板读取当前项目的实际取证任务，绑定`task_ref / state_version / snapshot_ref`。如果尚无任务，显示“先执行一次检查”，不妨碍创建、选择项目或已有候选操作。任务所需证据及其绑定可展开核对；后续分析提供的证据要求不改写原取证任务身份。

1. 选择1至8份原文件，每份不超过32MiB、合计不超过64MiB。填写每份来源的URL或本地资料URN、媒体类型及许可说明；页面不会访问声明的URL。支持UTF-8文本、PDF和XLSX保存值的既有读取器，不执行文件内容。
2. 每份文件可添加选区，总计1至32处。坐标默认留空，必须填写实际定位及该选区能说明什么；来源、许可和主张都仍是未核验声明。
3. 点击“登记资料，不读取”。宿主保存原字节、选区声明及任务绑定，产生回执；此步有原件I/O，但不产生提取行动、观察或FTS，不扣来源读取次数。
4. 核对“已保存的资料包”中的数量和未读状态，展开回执可下载登记JSON与逐份已捕获原件，完整SHA和声明保留在回执中。刷新页面仍从项目记录恢复该列表。
5. 回到上方真实候选，明确选择已登记来源、填写理由并执行一次。此时才调用选区读取，使用独立来源预算；完成后，已提取片段进入原来源reader与FTS引用选择。登记和读取都不会重复已完成的基础或分组分析。

| 定位类型 | 明确填写示例 | 坐标边界 |
|---|---|---|
| `text_lines` | `1-10` | 一基物理行，包含表头；不是CSV逻辑记录，单选区最多256行 |
| `pdf_page` | `3`或`3:0-800` | 一基单页；页内偏移按pypdf提取文本的零基Unicode码点，end排除；无OCR |
| `xlsx_cell` | `Sheet!A1:C6` | 实际sheet和单元格范围；只读保存值/公式缓存，不执行公式 |

原文件由宿主捕获后再读取，不能用声明的文件名、C2/C3等标签或可提取状态确认终点含义、独立性或科学映射。来源读取失败及原行动保留，不修改原件来伪装成功。资料登记或新选择会使旧快照报告过期，需显式生成当前报告。

实现分别在[资料面板](../frontend/src/local-evidence.ts)及[共享命令入口](../frontend/src/local-workbench.ts)。登记沿父页面原请求ID、冻结body、busy和CSRF提交；没有第二套自动请求器。文件、坐标与问题草稿仅保留在当前页面内存，切换项目后按项目恢复；重载不保留未提交文件，已登记原件与回执则持久保存。

## 明确授权有界连续推进

“有界连续推进”面板适用于已选择的当前项目。它复用原`ProjectController.advance`及父/子恢复，在一次明确授权内按本地条件规则逐步推进；不调用模型、不重新拟合，也不扩大方法白名单。

1. 勾选允许本批运行的本地方法。列表来自当前项目真实`method_options`，默认不勾选；勾选不代表该方法已经合资格，每一步仍检查前序反馈、完成状态、未知执行及原预算。已完成的结果不重复计算。
2. 若允许读取来源，逐份勾选当前已登记、未读的确切收据，可先下载回执核对。提交会同时加入对应来源方法ID，只能读这些SHA；未来上传的资料不属于本次授权。
3. 明确选最多1或2次行动，填写本次授权理由，再点击“按本次授权连续推进”。这是本批上限，不增加项目累计本地/来源额度、模型额度或原5元现金上限；历史费用unknown继续保留。底层API接受1至8，界面仅提供1或2。
4. 核对已保存批次的停止原因和每步父/子记录。没有候选、下一步未授权、达到步数或项目预算、失败及未知执行都会停下；上传、登记、刷新和重开均不自动启动批次。原单步选择、资料登记及报告按钮仍分别明确提交。

每批冻结原`request_id / project_id / expected_state_version / max_actions / allowed_methods / source_receipt_sha256s / reason`。页面显示最近8条批次及原授权、逐步身份、停止原因，并可下载完整原批次JSON。已完成批次的旧ID只返回原历史结果，不会延长授权或再走下一步。

响应丢失或推进中断时，只读刷新/重开会载入宿主保存的原body和ID；未完成记录提供“核对并继续原批次”，必须仍选中原项目且由使用者再次明确点击。此入口可以核对同批次的pending/uncertain，不绕过其他原请求；底层若有未知工具执行，仍停为`needs_review`，绝不重新派发未知行动。终止的`waiting / limit_reached / not_authorized / blocked / failed`记录已完成，不显示续行按钮。批次尚未收口时，新提交保持锁定，不能换新ID绕过。

## 错误、恢复与重开

创建/选择/单步推进/资料登记/批次/报告每次都冻结一个request ID及原JSON内容。普通错误保留课题、CSV、字段、理由及资料草稿；“用原请求ID核对／重试”只发送该次冻结body，不把编辑后的字段偷偷塞进旧ID。`INVALID_SPEC`等明确拒绝可编辑修正后用新请求提交；同ID改内容会被宿主拒绝。

网络缺回执、unknown、未完成操作或5xx不能视为未执行，页面不自动重发或换新ID；保留原ID并只读核对。GET返回的pending列表只含request_id/command/status/project_id，不含原payload或宿主路径。页面重开后恢复持久active项目和已保存结果，切换活动项目会清除旧context；不会自动执行候选。

资料登记的未确认请求按项目隔离：对应项目不能换新ID绕过原请求，仍可切换查看、操作其他项目；原ID及状态提示保留。原登记是否已进入核心账本由宿主核对，不能把缺回执当作“未保存”。页面不自动补登记、重新捕获或读取资料。

浏览器sessionStorage仅记request ID/command警示，不缓存CSV、提案原文或CSRF token。重载后若原body已不在内存，只读取持久记录并显示原ID，不凭新表单重造原请求。原未完成目录/账本不被删除或补造成功，unknown与预算门禁仍由宿主执行。

## 接口与只读边界

| 入口 | 行为 |
|---|---|
| GET `/api/local-workbench` | 启用状态、CSRF token、持久active项目、项目列表、限额、pending元数据及最近8条保存批次 |
| POST `/api/local-workbench/create` | 题目、预算归属、明确本地上限和CSV/spec Base64原字节；不接收自由宿主路径 |
| POST `/api/local-workbench/select` | 显式选择已保存项目 |
| POST `/api/local-workbench/advance` | 当前project/version及绑定真实context的受限proposal；只选候选id或等待 |
| POST `/api/local-workbench/evidence` | 当前project/version/task_ref、未核验contributor、原文件Base64、明确选区及remaining_questions；只登记 |
