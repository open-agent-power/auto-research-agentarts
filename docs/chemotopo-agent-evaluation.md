# P02 真实记忆闭环评估

## 成功条件

以下证据须属于同一冻结版本、同一新研究的真实调用，按发生顺序能够互相绑定：

1. 模型原始工具响应选择`remember_evidence`，参数未由操作者补填；引用本研究已执行检查与比较。
2. 对应研究行动已落账，数值观察持久写入记忆库且为active；来源、输入、分析身份和协议完全匹配。只有准备结果或dry run不算成功。
3. 模型随后选择`recall_evidence`，返回上述非空持久观察；空召回不算复用。
4. 再后续的实际请求包含对应记忆ID、记录身份及条件快照；模型的评议或下一步判断明确依据这些观察，并保留已知、未知及下一项证据要求。

第4项证明本次请求与决策确实接入记忆，不证明有无记忆的因果增益。模型理由和`review_evidence`中的解释始终是未获科学批准的判断；不写成已验证数值事实，不升级为科学结论。预算末位pause仅证明控制执行，不能单独满足第4项的研究判断要求。

## 最小开发与实跑流程

修改集中在上述闭环。先跑受影响路径的测试，再做一次针对契约、状态、引用和记忆边界的审查；修正发现后只重查变化或失败路径。没有新变化、失败或未决风险时，不重复全回归或整轮审查。

验证后冻结源码、协议、模型身份和原有费用边界，新建研究，以冻结的累计请求预算完成一次有界真实运行；可按进程分段恢复，但不清零预算、不重发未知发送、不修补模型响应。模型提前暂停或未完成闭环也保留为本次结果，不为凑齐动作追加调用。

运行后只核对与本目标相关的原请求/响应、行动账本、active记忆、召回结果、后续上下文及账户收据。报告逐项通过或缺失；真实结果触发下一处产品改动，避免把重复验证当作研发进展。源文件和收据保留在ignored `runs/`，文档只留简要结论与定位。
