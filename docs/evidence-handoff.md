# 从诊断转成可交接的取证任务

`evidence_catalog.py`读取封存的诊断、数值迭代、基线和HDF5清点JSON，核对快照链与来源身份，产生19项事实。每项保留来源代号与JSON路径；随目录保存原始JSON文本及指纹。它不重新打开Excel、HDF5或图像，也不调用模型。校验时重新构造事实与模板，不能只改一个数值再更新外层哈希。

研究只有四种动作：

| 动作 | 结果 |
|---|---|
| `read_evidence` | 读取模型指定的1～8项事实及出处；至少包含一项尚未读过的事实 |
| `record_next_step` | 选择已满足证据要求的任务，引用已读取事实，保存完整任务模板并进入等待外部输入的paused状态 |
| `pause`、`stop` | 不生成任务也可以结束；不强迫模型完成预设路径 |

任务模板由开发者设置，目前提供“作者导出映射”和“零对象转换规则”两项；不是模型自由设计的新实验。模板写明来源链接、CSV字段和验收标准。任务ID与事实ID由模型显式选择；观察身份、来源目录与最近反馈ID仍由宿主绑定。模型理由原文标为未审定，任务落库不代表外部取证已完成或生物终点已确认。

## 运行入口

准备和只读导出不调用模型。实际执行沿用已有免费Ollama范围和固定累计请求上限，最多4次；显式传已有`--model-store`与本次`--max-new-requests`。重启不重置预算，未知发送不自动重试，无付费回退。平台仍暂停。

生成任务后，新的输出目录含`handoff.md`、`handoff.json`、`source-index.json`及四份`evidence/*.json`，队员能按事实的JSON路径回到随包文件。它们是已有检查记录，不能冒充新取得的作者数据。只读状态入口仍为`scripts/research_status.py --workspace <目录>`。
