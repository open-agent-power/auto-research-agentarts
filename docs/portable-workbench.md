# 可独立打开的只读工作台

交接包保存已有基线、可选迭代报告和后续研究记录，供队员在另一台电脑阅读五页工作台、对比指标、下载PDF与复核包。只需Python 3.11或更新版本的标准库；不读取原始xlsx，不安装numpy，不运行模型或拟合，也不能继续研究。

## 当前推荐：一份配置制作完整工作台

主开发使用产品根目录的`config/workbench-p02.json`，其中11份科学来源及1份综合报告的路径与预期快照均明确列出，包含基线、数值迭代、来源读取、管线研究和表格评议；不按目录日期猜测最新版。

```powershell
.venv/Scripts/python.exe scripts/publish_workbench.py inspect
.venv/Scripts/python.exe scripts/publish_workbench.py build --output runs/next-delivery --select
```

相对配置路径、来源和输出均按产品根目录解析；也可以从其他工作目录用脚本绝对路径执行。`inspect`只检查明确配置的来源，不能替代作者数据或科学验证；`build`复用既有打包器。源快照与配置不一致时，创建输出和切换工作台之前即停止。新包生成后再核对清单中的12份快照；只有显式`--select`才更新本机选择，不启动/终止浏览器或服务。

配置不带凭据或研究数据库，也不随Git复制ignored运行产物。资料不在本机时，接收现有独立包即可；不要为了凑齐目录重新推理或训练。需要换来源时，应显式修改对应路径和真实新快照，其余历史仍保留。

下面保留早期单项/分项打包方式，便于查历史。

## 队员操作顺序

1. 将ZIP解压到新目录，进入该目录，运行`python -I -S serve.py --check`。校验失败先保留输出并反馈，不编辑清单绕过。
2. 运行`python -I -S serve.py --port 18773`，按终端地址在浏览器打开`http://127.0.0.1:18773/`；端口冲突可用`--port 0`自动分配。窗口保持运行，结束时按Ctrl+C。
3. 阅读总览、研究、实验、知识与成果；按照各记录的具体实验与来源比较，不把不同来源的拟合次数相加冒充模型训练，也不把历史PDF当作最新诊断或评议。
4. 下载需要的PDF或复核ZIP。复核ZIP另解压到一个新目录，运行`python -B verify.py`，仅用标准库独立检查保存数值，新增拟合0次。

清单中的SHA、大小与快照匹配证明封存内容一致，不是重新做作者来源或科学验证。PDF仍是本机证据报告，不是已发表论文；原模型理由与宿主数值事实分开，ALP资格仍未批准。

## 带回什么反馈

记录包的快照SHA、页面名称与涉及的比较规则／alpha；界面问题附截图及浏览器／屏幕尺寸，数值问题附`--check`或`verify.py`原始输出。不要只反馈“模型成功／失败”，应指出哪个指标、哪份记录与预期不同。

这份包不能证明华为接入、新课题研究或模型训练成功。继续开发须回到原Git项目、对应参考原件与原有云额度规定；包内页面操作不会创建新研究。

## 固定本机入口

开发仓库用 `scripts/workbench.py select --bundle <已解压包>` 明确选择，再运行 `scripts/workbench.py serve`；默认仍为18784。`status`仅核对当前选择及清单身份，不代替包内文件校验。打开旧端口看到的仍是旧封存版本，不会随新包自动变化；选择后重启当前服务并整页刷新。命令详见仓库README。
