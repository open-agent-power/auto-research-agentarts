# 真人使用与同项目交接

两位队员在同一工作台先后操作同一课题，保存实际判断、行动与反馈。主持人先确认可用的本机服务地址、manager目录、项目身份和剩余额度。工作台入口与功能见[本地用法](local-workbench.md)，整体完成条件见[提交计划](research/submission-plan-20261130.md)。

## 准备课题与入口

主持人把实际服务URL、课题名称和`project_id`交给两位使用者，并在“项目总览”核对当前state、计划版本与已保存工作。使用原manager目录继续已有项目。新课题由使用者提供真实问题、CSV、每行含义、数值与分组字段、目标及单位、来源和使用条件。

原始数据训练设计还需明确目标之外的数值特征，以及已声明的分组字段。执行要求至少10条完整记录、2个完整组。由材料提供者说明这些组代表什么，以及按组拆分是否对应实际研究问题。

在“研究推进”的“研究设计与验证”中选择原始数据训练设计，勾选特征和拆分组，填写采用理由，再明确保存。固定方案为随机五折（seed 11）与分组`min(5, 组数)`折，Ridge alpha为1，标准化器在每个训练折内拟合。保存预测设计则需另行选定CSV已有的预测列，并说明预测产生过程。

本地工具额度与fit额度分别核对。新建项目默认2次本地工具调用，若要完成质量核对及三项设计检查，须在创建时明确选择足够的累计上限。训练设计的fit尝试上限默认20、可选1至40，每个交叉验证折分别包含1次标准化器fit和1次Ridge fit。页面显示累计已用、预留、模型拟合与预处理拟合；后续采用设计继续读取原消耗。

## 查看模型计划条件

研究推进的模型计划卡会显示“计划执行条件”，包括请求准备时版本、扣除预留后的三类剩余额度、当时可执行候选及方法缺口。先区分现在能做的行动、需要补齐条件的后续工作和纯粹的等待／复核计划，再决定采用或拒绝。来源读取有余额不代表已有可读选区；来源确认也不会补回本地工具或拟合额度。历史卡片显示冻结条件，当前执行仍由控制器重新核对。科学解释需要另外审阅，不能把这块条件说明当成质量批准。

## 已收口课题的判断接续

[Auto MPG课题](research/auto-mpg-year-study.md)已完成预登记计算，本机完整入口为`http://127.0.0.1:18818/#/research?focus=design`，项目`project-4dfdc54c0c4e4d008ee1f7b2387f0a69`、收口时state30、计划v3。模型CLI关闭，本地显式意见和报告操作开启；拟合12/12、工具4/4、来源1/1，不能为了交接动作再执行检查。

两位真实使用者可顺序核对三个具体问题：子版优于训练均值参考是否代表优于含年份父版；MAE变差但负预测减少应怎样表述；候选负对照能否检验年份增量价值。分别先独立阅读，再保存本人意见及所引用记录，第二位回看前一意见后记录保留或修订理由。保存意见后沿同一项目生成当前报告，记录实际反馈ID和新state。

该方式能取得阅读、判断和交接的实际反馈；没有新研究行动时，只能报告判断接续，不能填成两位真人已完成带后续行动的研究闭环。代理原回答、算术审计及操作者代理意见也不能计为真人使用。

## 第一位使用者

1. 从“项目总览”说明自己要解决的问题，核对材料和现有结论。在“研究推进”保存或按需要修订计划，写出预期结果及什么反馈会改变路线。
2. 打开“开展下一步”，核对实际候选和理由，明确执行一次合资格行动。训练设计可先完成质量检查及随机五折验证，后续分组验证与负对照留给接续者。
3. 在“实验中心”阅读实际结果，核对指标、划分或来源记录。说明目前支持什么判断、哪些竞争解释仍存在，以及下一步准备做什么。
4. 在“研究者反馈”填写自己的自填称呼、判断或卡点、后续建议，并关联对应行动。保存后记录反馈ID与当前state。
5. 在“成果与复现”生成当前快照报告，记录交接时的项目、计划与未决行动，交给第二位使用者。

遇到真实材料不足、额度不足或未决请求时，保存当前停点与具体缺口。网络缺回执时先只读刷新并核对原请求ID，恢复规则见[错误与重开](local-workbench.md#错误恢复与重开)。

## 第二位使用者

1. 打开同一服务，在“项目总览”选择交接的原项目，核对`project_id`、state与计划版本。先说明从现有记录理解到的问题、已知结果与下一步。
2. 找到第一位使用者引用的行动或原文，写下自己的判断。按需要修订计划，或说明继续原计划的理由。
3. 从真实候选中选择一项后续合资格行动并明确执行。例如核对分组验证结果是否改变随机划分下的判断，再按保存的划分查看负对照。
4. 用自己的称呼保存反馈，关联本次行动，说明对前一判断的保留、修订或停止理由。完成后的下一决定或当前报告随项目保存。

主持人记录提供过什么帮助，以及使用者在哪一步被阻断。修复具体卡点后，安排原使用者复看并保存新的意见。

## Limitations

反馈作者为自填身份，系统保存其原陈述与信任标记。真实性和两位实际操作者的参与由本次使用记录确认。代理试用、工程夹具和只读评阅各保留原用途。

该流程采用同机、同manager的顺序交接。报告导出用于阅读和核对，跨机器恢复完整项目另需相应的交付与恢复验证。模型、来源、工具及fit用量沿原账本累计，既有现金上限与历史未知费用继续保留。

训练和误差比较的解释依赖数据、样本与拆分含义。负对照按其协议标明OOF折内或组内条件诊断，使用者结合划分、置换方式与结果作出判断。真实使用帮助以本次实际解决的未知、改变的决定或减少的重复劳动说明。
