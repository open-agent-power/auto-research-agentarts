## 第一优先：独立复现一次完整工作流

1. 在自己的本地 checkout 按 README 准备 Python 环境，运行：

   ```powershell
   .venv/Scripts/python.exe -B agentarts/c01-sensitivity/test_code_node.py -v
   ```

   保留实际测试输出。SciPy 或 ignored 冻结 CSV 缺失时，测试可能明确跳过；逐项记录跳过原因，不填写“全部通过”。需要冻结证据时向主控索取只读副本，不自行编造 CSV。

2. 按项目 skill 先确认中国站登录；未登录时默认进入**华为云账号的华为云APP扫码页**，等操作者扫码及手机确认，再核对真实返回的账号、区域和控制台。不要误用“华为账号 / HUAWEI ID”二维码。已有正确会话就保留，遇到二维码缺失或风险提示先交接缺口。随后创建**个人副本**，例如 `c01-repro-姓名缩写-日期`。同账户协作也必须各用不同草稿 ID；原有共享草稿只供只读参考，不同时编辑，不覆盖、不删除。

3. 按工具说明搭成“开始 → Python 代码 → 结束”，沿用仓库代码和公开输入，核对 `query`、`result` 的类型与引用。异常设中断、不重试；不加入模型节点，不使用 AI 生成代码，不创建 Runtime、代码解释器、存储或其他收费资源。

4. **调用前与主控核对团队累计费用记录和剩余可用额**。统一记录由主控保存在 ignored `.agent/team-budget.json`，向主控索取最新脱敏记录，拉取代码不会自动获得当前费用状态。团队新增模型及云服务现金支出合计上限为 **5 元**，不是每人另有 5 元；免费额度、模型用量及关联服务费用也要分别记录。权益、价格或累计消耗不清楚时，先提交缺口，不启动可能收费的执行。

5. 仅做一次计划内的 8 样本完整试运行，核对三个节点的实际输入和输出。失败或结果未知时先留证并核查原因，不自动反复运行。已有演示中的删样本云试验无需再做。

核对基准如下，浮点绝对误差允许 `1e-12`：

| 项目 | 预期 |
|---|---|
| 样本数 | 8 |
| canonical 输入 SHA-256 | `da623d987f74cdc00610ff403225c8ecc0761bb46e58bf6530e77d744bf541ed` |
| 全部样本 Pearson r | `0.5234731822584694` 附近 |
| 剔除 Alloy 4 后 Pearson r | `-0.7788568345407015` 附近 |
| 方向改变次数与状态 | `sign_changes=1`、`needs_review` |

记录所用 Git commit 和代码文件 SHA-256；不能只凭节点变绿或耗时相近判定复现成功。`needs_review` 表示诊断触发复核；`exploratory_only` 也不表示通过科学验证。本任务只证明独立的控制台脚本工具可复现，不表示本地持续研究循环已经调用云端工具。

## 同一交付中核对正式评分依据

先向负责人取得**当届、当赛区、当赛道／赛题、当阶段**的正式通知、作品模板及评分文件，沿文件中的主办方官网或通知链接回源。仓库里的 AgentArts 产品文档不是赛事评分规则。本产品仓库没有承诺已收齐当前正式评分材料；只有本仓库的队友应向主控索取，完整 ICT 工作区中的 `资料/` 赛事原件也只能作为待核对入口。

只整理与当前作品直接相关的要求：要求交什么、如何证明、是否有明确权重、我们现有证据或缺口是什么。每项保留正式 URL，或文件名、版本／发布日期、适用范围与页码。找不到正式原文就写“未确认”；聊天里的“踩分点”“闭环跑通”不能换算成评分权重，旧文件与新通知冲突也不要自行裁定。

## 明确交付两份文字和一组运行证据

在自己的分支准备 `docs/team-submissions/姓名缩写/日期/` 下两份文件，由主控复核后合入：

- `handoff.md`：记录本地环境与测试结果、实际平台区域、个人草稿名／ID、运行时间与平台运行标识（如有）、代码 SHA、输入 SHA、关键数值对照、费用复查时间及累计记录引用。结尾分清“已复现／未确认／下一步”。附证据相对路径；没有原生导出包就明确写没有。
- `scoring-evidence.csv`：列为 `正式要求,权重原文或未确认,来源URL或文件名,版本与适用范围,页码或章节,现有交付与证据,缺口`。只填查到的要求，不补造完整评分表。

实际运行证据留在被 Git 忽略的 `runs/team-姓名缩写-日期/`：`local-tests.txt`、`cloud-result.json`、一张覆盖开始／代码／结束成功详情的截图，以及调用前后用量复查记录。若平台不能导出 JSON，保存手工复制的实际输出并注明来源，不冒充平台原生导出。费用记录与截图不得暴露 Cookie、密钥、会话、手机号或其他账号信息；不把运行产物提交到 Git。向主控交接时只提供必要的脱敏片段，不发送登录状态。

完成标准：代码与输入身份可核对；完整工作流实际结果与上表一致；成本与资源状态有记录；赛事依据能回到正式原文，未知项明确保留。未能运行时也可交付具体阻碍、已做步骤和安全停止位置，但不能标成平台复现完成。

## 第二优先：补齐少量科学复核线索

第一优先完成后，或平台因权益／费用受阻时，再围绕下面最多三个问题查资料，不要求重做文献综述或下载整批数据：

1. 合金与生物标签的明确对应依据，以及 B24–B31、标签星号能否从作者资料确认。
2. 与当前分析直接相关的字段定义和单位；区分已确认的 ALP/DNA 归一化、未明的 DNA 换算及 ARS 的 21／28 天冲突。
3. “每合金／时间点三次测量”是否是独立批次，哪些结果仅代表 8 个合金聚合样本。

入口：[C01 工具署名与限制](../agentarts/c01-sensitivity/README.md)、[Mendeley Data V1](https://data.mendeley.com/datasets/tt7gwkpck8/1)、[对应论文](https://doi.org/10.1016/j.bioadv.2023.213572)。完整 ICT 工作区另有 `references/auto-research/08-c01-tnzst/README.md` 的原包及人工核验索引；克隆中没有时向主控索取，不把路径缺失当成已否定证据。

可增交一份 `data-check.md`，每个问题只写“现有说法、原文位置与链接、确认或仍缺什么、对分析的影响”。允许保留未确认；不能用图中的显著性星号解释样品标签，不能将重复测量扩成更多独立合金，也不能自行改写公开输入、原始快照或报告数值。
