# 知识查询中的字母数字拼法

`KnowledgeIndex.search` 和调用它的 `project_knowledge.query` 支持部分相邻 ASCII 字母与数字的不同拼法。例如，`top20` 可额外尝试连续短语 `top 20`，`Factor47` 可额外尝试 `factor 47`；反过来，`top 20` 和 `Factor 47` 也会尝试相应的连写形式。原有查询词仍参与检索，原词和已有中文别名优先，新增拼法只占用 64 个查询词上限内剩余的位置。

查询仍限制为 1–512 个字符，返回数量 `limit` 为 1–8。使用现有冻结索引，不需要重建索引。查询的来源范围、引用和警告保持原有约束；返回的是有来源的摘录，不是事实确认或科学结论。别名会改变参与匹配的词，因而可能改变 BM25 排序和有界 TopK 的内容；不能保证结果是原结果的超集。

使用时应注意以下边界：

- 连写查询生成的拆分形式是有序连续短语。空格查询仍保留原有的 OR 检索，例如 `Factor 47` 原本也可能命中 `Factor 87` 或不相邻的词；新增连写别名不会消除这些宽匹配。
- 现有索引构建会丢弃单字符词。因此，`x1` 查询不能依靠拆分短语找回原文中的 `x 1`，`x12` 对 `x 12` 也有同样限制；别名无法恢复索引中没有的词。反向查询可能命中连写形式。
- 合写别名只连接相邻的字母和数字，不能跨标点、其他词或制表符。按现有 NFKC 规范化后可处理全角等兼容字符；字母数字紧邻其他 Unicode 词字符时，不将其中一部分当作独立标识符展开。

知识检索与方法经验是两条独立路径。`project_knowledge.query` 检索项目已引用的知识索引；经验记忆依原有精确 scope 检索，只有显式导入且符合现有条件的 active 案例才进入方法上下文。经验不会因为本次拼法兼容而自动进入 FTS，也不会自动成为当前证据或候选。

验证使用手造文档和真实 SQLite FTS。七文档的前后对照与37项相关测试的精确SHA和云盘证据路径见[验证索引](execution/g5-local/knowledge-query-spellings-verification.json)；原始日志保存在ignored runs，不声称公开仓库已附这些原件。这些证据只覆盖有限手造样例，不证明真实语料召回率提升或研究收益。
