# 实验后提出下一步并保留观察

| 行动 | 保存的内容与边界 |
|---|---|
| propose_next | 继续调参、换假设或停止方向，以及结构化假设、验证办法、成败条件；均为未验证建议 |
| remember_observations | 宿主从实际结果提取数值观察，与模型决定分开保存；不把建议升为已验证事实 |
| recall_observations | 精确scope召回适用记录，不自动恢复退休／撤回记录 |
| pause／stop | 任一步均可结束；不强制提案或写记忆来凑成果 |

## 创建与恢复

新研究需要已完成来源研究、封存基线、独立记忆目录及不超过2000字符的目标。只准备／读取状态：

零请求模式不启动模型、不消费待执行响应、不拟合。实际授权调用另提供`--model-store <原有模型目录> --port 11448`和本次有界`--max-new-requests`。恢复使用同一workspace、新output，来源、目标及记忆目录可省略；显式值须与冻结配置相同，累计max_requests不可重置。

收据目录不能覆盖或与研究、来源、记忆目录交叠。提案不是新的执行授权：追加拟合、换候选或新课题需另建明确协议与研究。原始模型理由及提案仍未科学审定，ALP资格、已见探索折与免费额度规则不因新增记忆而改变。

## 在工作台查看这次失败与记忆

`--assessment`可省略；提供时只接受绑定实际来源与提案的`unreviewed`或`needs_revision`开发核对，不能标为批准。导出过程核对请求—响应—行动绑定及实际召回内容进入后续请求，不运行模型或拟合。交接包只增加一份有哈希绑定的JSON；已有迭代PDF、数值复核ZIP和基线工件字节不变，因此旧PDF不包含这次研究收尾。旧包未提供postrun时接口仍返回404。

## 接续失败提案：有界修订

继续调正则化必须提供有限的`candidate_alpha`，并与实际清单去重；其他方向必须为null。检查使用结构化值，不从一句“不要重复alpha100”误判为重复实验。仅通过这个检查仍不证明建议有价值；自由文本中的科学判断依然未审定。

`remember_revision`明确表示：保存当前修订与原数值观察，退役指定的旧模型提案记忆。原文和退役事件仍保留，两条数值记忆的ID与内容不变。跨库操作先留下pending记录，中断后用同一请求幂等恢复；完成前不能发送下一次模型请求。记忆保存后锁定修订，可显式召回，再暂停或停止。修订、写记忆和召回均可不做，末个请求只允许控制动作。
