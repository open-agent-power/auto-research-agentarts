## 开始工作时的提醒

用一句话说明本轮要改变的用户行为或能力，以及沿用的设计/实现入口。索引中的“待建”只提供方向，不能当作已存在的 API 或执行器。

先核对当前计划处于架构还是实现阶段；用户要求先做底层架构时，交付职责、依赖和契约设计，不自动开始下一阶段控制器编码。

产品主线是可继续的自适应研究；配方表示可实例化比较的研究设计，科研配方与本开发 Skill 分开。保持既定 UI 系统，避免为每个案例另建同构控制器或界面主题。

在原授权内完成工作。平台操作另读已有 [AgentArts 中国站 Skill](../agentarts-china-builder/SKILL.md)；本 Skill 不新增云操作、费用或代码执行授权。

## 持续开发与团队调度

用户已授权持续推进时，每个可验证增量完成后保存事实、短报进展，再继续下一项可做任务；定时检查是对齐和汇报触发，不是停止工作的指令。只有实际执行窗口结束、环境不可用或需要用户决定的新阻塞才保存交接，不假称会话结束后仍有常驻模型。

先核实际可调用的已有成员，优先续派并按任务调整角色，允许同一成员兼实现、相关测试、界面和打包。默认团队池含主代理和各级子代理至多10个成员，服从宿主更低的总量/并发限额；不因每个小目标另建成员或层层拆分。新建子代理优先gpt-6.1-terra、ultra，按宿主参数约束fork_turns=none并提供必要上下文；已有成员不为换模型重建。独审由未参与对应实现的其他成员承担，团队由主代理统一安排依赖、文件所有权和交付。

## 完成工作时的提醒

- 新模块、组件入口或接口变化：同步相应索引；接口细节仍以实际服务和调用方为准。
- 产品目标/适应策略变化：同步 docs/plan.md 或正式研究设计；实验事实留在原账本，不改成理想结果。
- 选择与改动匹配的验证，完成后收口；不因普通文档或 UI 改动重跑历史模型、拟合或全量 review。
- 只提交可共享索引、Skill、正式设计和本轮实现；focus、浏览器状态、凭据与运行证据继续忽略。

## 加载边界

这是项目内开发提醒，依赖宿主遵循 AGENTS 或显式加载此文件。本轮没有安装自动 hook，不能承诺所有工具都会自动发现 `.agent/skills/`。若工具未加载，在任务中提供本文件和对应索引即可。
